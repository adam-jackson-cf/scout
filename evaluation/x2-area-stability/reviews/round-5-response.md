## Judgement calls

1. **Citability precedence (issue 1).** An inconsistent arm A gives `not citable (arm A …)` whenever A adopted, even if B fails (no §4 consequence applies). An inconsistent arm B gives `not citable (arm B …)` only when it would otherwise be `replicated`; a failing B stays `not replicated` because the consequence (codex-scoped proposal) is identical. Synthetic scenarios have no `tool-versions` files, so their own `analyze` output is `not citable`; the replication rule is tested by direct calls with explicit flags.
2. **Sandbox refusal (issue 4)** applies to both arms and to a blank value, although Clawpatch ignores a blank override: the same presence rule as the other refused names. `workspace_dirty` is recorded and reported but has no verdict consequence; the dirty case is tested at render level only (the stub never writes to the checkout).
3. **`cli_versions_changed` type (issue 3)** changed from a list of repositories to a dict of distinct values per key, as the council asked ("report the distinct values").
4. **Presence as flag input (issue 5)** is an analysis-time reason, since the collector cannot refuse after the before-probe (§2).
5. **Checked fact (issue 5b)** was produced by this response (tree listings of blob-less clones; I did not rely on the addendum's unstated matching).
6. **Optional (issue 6a)** codex effort banner recording not implemented.
7. **README/§9 `setsid`/`tmux`** remain unexercised; only `nohup`'s ignored SIGHUP is tested.
