### Minor

**2. The `claudeEnv` port copies every case-insensitive `path` key; Clawpatch copies the first and stops — and validation pins the port's behaviour.** `common.py:117-119` (`for key in base: if key.lower() == "path": copy(key)`) vs `claude.ts:304-311` (`copyPathEnv` returns after the first match, even if `copyEnv` copied nothing because the value was empty). `validate.py:432-438` supplies both `PATH` and `Path` and requires both in `want_names`, so the check asserts the unfaithful behaviour. Realistic only with duplicate spellings in the operator's environment, but the study's claim is "the environment of `claudeEnv(host)`", not "approximately". Fix: `break` after the first matching key; the unit check supplies both spellings in both insertion orders and an empty first match and expects exactly Clawpatch's result; the drift guard (`validate.py:443-448`) additionally asserts `replaceEnv: true` is present in `claude.ts` (the replacement is what makes `ANTHROPIC_MODEL` unreachable, `exec.ts:67-72`).

**3. The SIGHUP handler cancels the `nohup` that README and §9 recommend.** `collect.py:364-365` installs `_term` for SIGHUP unconditionally; `nohup` protects by setting SIGHUP to `SIG_IGN`, which `signal.signal` replaces. When an SSH session drops, the interactive shell re-sends SIGHUP to its jobs **[INFERENCE: bash/zsh job-control behaviour]**, the collector aborts with `aborted: KeyboardInterrupt: signal 1`, and the append-only preflight refuses any rerun — exactly the loss the recommendation exists to prevent (README `:27`, §9 `:199`). Fix: install the SIGHUP handler only when `signal.getsignal(signal.SIGHUP) is not signal.SIG_IGN` (the inherited ignore wins; SIGTERM unchanged); validation starts a collector with SIGHUP ignored (`preexec_fn`), sends SIGHUP, and asserts it keeps running to completion; the existing SIGHUP check (`validate.py:1221-1239`) stays for the non-ignored case; §9/README say which protections apply (`nohup`, `setsid`, `tmux`).

**4. No preregistered consequence when the probes disagree; CLI versions are recorded only at start.** §2 `:39` and §10 `:212` say a roll between the probes "is reported" and that "a different version or model needs a new study … is checked against the probes", but no rule says what RESULTS may claim when, within an arm, a probe fails, before ≠ after, or fastapi ≠ axum (ABBA puts arm A's two collections at the two ends of the window, so a codex roll most likely splits the deciding arm). `analysis.py` never reads the probes (no "probe" in the file); `render` does not print them. `claude --version`/`codex --version` are taken once in `tool_versions` (`collect.py:316-322`) before any map; Claude Code self-updates, so a version change inside a 1–2 h collection is plausible and invisible. Fix: §2/§10 preregister per arm: *consistent* iff all four probes were taken without error and name one model; otherwise the arm's verdict is reported with the deviation and is not citable for a design change (design rule 3, "Clawpatch 0.7.3 and default models only"); `analysis.py` computes `probe_consistency` per arm from the `tool-versions-*` files (already loaded in `inventory`, `:392-397`) and `render` prints each (arm, repo)'s probes and the flag; `collect.py` records the CLI `--version` again beside `model_probe_after`; one validation case with a fake whose after-probe names another model asserts the flag and the rendered line.

**5. The setup window after the before-probe is outside the abort bookkeeping §9 promises.** §9 `:199`: an abort "after the preflight and the before-probe … writes the same record". `collect.py:371-387` (workspace creation, clone, checkout, `tool_versions` — up to four bounded `--version` calls — and the first `write_versions`) runs before the `try` at `:398`; a signal or `sh()` exit there (`:53-59`) writes no stop record. Nothing is recorded in `data/` in that window except in the microsecond between `write_versions` and `try`, so no evidence is lost, but the frozen text is inaccurate. Fix (either): extend the protected block to start right after the before-probe with a `phase: setup` record (`stop_path` defined first, `tv` guarded), plus a deterministic setup-failure fixture; or §9 states that an abort during clone/checkout/version collection leaves no record and no data file, and the rerun needs only the workspace removed (the message at `:378`).

**6. Interpretive text RESULTS.md would repeat.** (a) §5 `:154` "A `different` call on a match with a near-identical file set indicates a labeller that over-calls `different`" and `analysis.py:326-327`, §7 `:180` "the only descriptive look at the opposite error": GUIDE R1/R3 (`GUIDE.md:28,30`) make `different_concern` the *correct* answer when the stated purposes differ on the same files, which under §3.3 is a real spurious merge; the band share cannot separate over-calling from a mapper re-description. (b) §3.7 `:116-117` "Out-of-sample view": the held-out transition shares prior maps with the remaining ones (F1 in T1–T3; R1, R2, M1 in two each) and can share pair ids and labels (`build_pairs.py:113-115`), so LOTO understates selection; say so. (c) §6 `:162`, `analysis.py:53-55` and the render label `:459` say "session counts": `label_models` counts call rows and keeps only the final attempt's model (`label.py:114-128` overwrites `resolved`), so a retried call is one row, and a model seen only on a failed first attempt is not recorded; rename to "call rows (final attempt's model)" and state the limit, or record per-attempt models — do not multiply by `attempts`. ## 4. Adjudication of DRAFT-NOTES choices 17–22

17. **Joint LOTO without re-applying the gates — accept.** The gates are properties of the whole data set (class counts, unlabelled share at `T_MIN`, pooled controls); re-applying them to a 5-transition subset would trip the class gate whenever the only mutation transition is held out. Consequence to state in §3.7 (issue 6b wording): holding out the only measured mutation transition selects `t*` from remap transitions alone.
18. **Session accounting by rename — accept** for `codex_sessions`/`pairs_with_exec_event`; the `label_models` label is issue 6c.
19. **Over-call denominator = labelled matches in the band, occurrences, `None` when empty — accept.** Denominators are rendered. No scenario puts an unlabelled match in the band, so the denominator choice is verified by reading (`:328-332`), recorded as a limit, not an issue. Interpretation is issue 6a.
20. **ABBA — accept.** Arms are different vendors, so a model roll hits one arm; ABBA puts arm A at both ends of the window, so a codex roll would most likely split the deciding arm across repositories — visible in the four codex probes, which is why issue 4 asks for the consequence to be preregistered.
21. **Abort bookkeeping — accept** the design; the `nohup` interaction is issue 3, the setup window issue 5.
22. **Revision 4 — accept.**
