## Judgement calls for the council
1. **Reuse as X2b**: everything but the collector by import and SHA-256 pin; the collector is a copy with a pinned diff (115 diff lines). X2's `analysis.py` is reused by *feeding it Jev rows in the replay schema* (arm `<arm>+jev`), so both methods are decided by one frozen rule and need no second analysis. Cost: the Jev rows' `created/kept/retired` are derived (descriptive only) and `jaccard` carries the Jev score; X2's "Jaccard" labels in the rendered tables mean "match score" for Jev cells.
2. **Candidate set = every pair sharing ≥ 1 owned file** (asked for as "includes pairs the Jaccard rule misses"). One labelled set serves both methods; the Jaccard matches are a verified subset. Alternatives considered: only pairs with Jaccard ≥ 0.10 (fewer labels, but an arbitrary floor that would hide exactly the redrawn pairs), all pairs (n² labels, infeasible). Estimated size ≈ 2.5–3 k unique pairs (X2b luna: 152 fastapi + 564 axum occurrences per arm).
3. **Choice, not Score or Noul, for the one question.** The shared client `internal/decisions` strips a Score's levels (`BuildRequest`), the route's Score semantics are undocumented, and the user asked to reuse the client. Choice over the guide's four labels gives the cookbook's three outcomes plus `cannot_tell`, with the guide's definitions as criteria verbatim (jev-actions labeling rule) and a permuted option order. `s = mean over the two orders of P(same_concern) + P(overlapping_concern)`, greedy order (−s, −P(same), ids) (round-1 issue 3: C2 counts only `different_concern` as spurious, so `overlapping` is an accepted continuation); the other probabilities are stored. If the council wants a Score, the product client must change first (out of scope).
4. **Both presentation orders averaged** (jev-actions pairwise rule): twice the requests (cents), removes an order artefact (validation S2).
5. **Jev cells decided like Jaccard cells, plus cross-repository confirmation for both** (jev-actions dev/test by repository, scoring the other repository once). Two-fold rather than a fixed dev/test split because a fixed split leaves fastapi (small) as the only unit on one side. The confirmation is a gate on *eligibility* applied identically to both methods; it is stricter than X2/X2b (which had none), so an X2-style `adopt` can be `ineligible` here.
6. **Haiku at effort `none` (default), `haiku-low` out; no fifth arm.** `haiku-low` is excluded to save collection time only (scope decision, main agent 2026-10-28); haiku default is kept because the user asked for haiku and one smoke map is a single draw (round-1 issue 1(b): the earlier "expected to fail the coverage guard" reason applied equally to haiku default). Reversible by adding an arm row, a collection pair and two cells.
7. **terra at `none` and `low`** (both ends of "lowest suitable"), luna-xhigh as reference (a second draw of X2b's configuration).
8. **Cost not measured, wall time decides.** Clawpatch prints no tokens/cost; no unmeasurable tie-break is used. Selection: fastest eligible refresh time; 10 % tie band; Jaccard preferred in a tie; then margin; then table order. The 10 % band, the 0.5 coverage floor (main-agent decision 2026-10-28, option B), the 1 % unscored limit, the 0.10 USD and 300 s Jev caps and the 8 workers are **[ASSUMPTIONS]** with no data behind them; the council may set them.
9. **Coverage guard** is the only mapper-quality control (owned files per map ≥ **0.5** × reference), a deliberately crude proxy; without it the fastest mapper would win by mapping least. Floor 0.5 (option B, main-agent decision 2026-10-28): the user asked for haiku and the lowest suitable terra effort to be compared and 0.8 would exclude them by construction; the area ratio is reported, not gated. On the smoke counts haiku default on fastapi (≈ 0.45) is expected just below 0.5; every other requested arm clears it.
10. **Served check replaces X2's probe-consistency citability** (X2b's solution), generalised to four arms; claude's served effort is only *requested* (the CLI reports none), stated in the record (`reasoning_effort_source`).
11. **The Jev scorer is Go, inside the repository**, importing `internal/decisions` and `internal/policy` (client, pin check, Redact, version key), not Python: no second client. It runs `go run ./evaluation/x2c-mapper-comparison/jev` under the module; the code under test therefore includes `internal/decisions` and `internal/policy/consent.go` (digests above) and the run must use a worktree at the run commit.
12. **Stub Jev scores are planted by title family** (`Concern/Redrawn/Volatile/Trap`), so the planted effect (Jaccard `fallback`, Jev `adopt` 0.85) tests the pipeline's arithmetic, not any real Jev behaviour; nothing about real Jev accuracy is claimed.
13. **Unmeasured by design**: mapper token/dollar cost; the served effort of claude.
14. **`run.sh collect`** runs the 8 collections in one shell loop and stops at the first failed invocation (an invocation that records a stop file exits 0 and the loop continues: its stop record is the deviation record, as in X2).
