## Verdict: ISSUES FOUND — do not run.

## Blocking

**1. Hidden-coupling proxy unvalidated and code ≠ preregistration (gap 1).** `collect.py referenced()` matches the partner's file stem as a word anywhere in the source (comments/strings included); generic stems (`utils`, `types`, `config`…) will mark most partners "explained", while Go/Rust package imports never mention a file stem, so the proxy is language-differential. Prereg §3.1 defines "hidden" per (f,g) pair, but `collect.py:203-221` keeps one `via` file per partner (highest confidence) and tests the reference only through it, so a dependency via another touched file is missed. No gate exists (DESIGN-NOTES §9.3). *Fix:* add **G7**: blinded annotators judge static dependence on a sample stratified by language × explained/hidden, with preregistered precision/recall thresholds and the consequence of failure (H4 exploratory only); make `n_hidden` count a partner as explained if **any** qualifying touched file references it (or change the prereg text); add a unit test.

**2. Floored primary outcome conflates H1 with H2, and the harness hides it (gap 3).** `harness.py truth()` defines "truth" as the estimator's own large-sample value, not the planted parameter. In `recover_floor` the T1 reference is 0.266 against planted β₁=0.15 (`harness-results.json`): with a floor, a planted *dispersion* effect (θ₁=0.30) raises the mean of the floored outcome, so an H2 effect would be reported as an H1 effect. Coverage there is 0.85 (T1) / 0.82 (T3). 38 % of T1–T4 rows sit at the floor (`gates.json G3`), and sensitivity (a) conditions on `n_commits ≥ 2`, a post-treatment variable. *Fix:* (i) harness reports bias against the **planted** value for T1/T2/T5 and has preregistered pass tolerances (rule 4); (ii) preregister the single-commit handling explicitly — recommended: a two-part primary (logit P(≥2 commits) + conditional log active-hours, both in the Holm family, or Tobit at the floor) — or state that T1/T2 estimate a floored-projection slope that mixes location and dispersion and that H1/H2 are then not separable; label sensitivity (a) as post-treatment conditioning.

**3. Validation gates G4/G5: blinding leak, unscripted annotators, manual override (gap 2).** `validate.py sample()` assigns pair IDs inside the stratum loop *before* `rng.shuffle(ps_rows)`, so `P000–P099` = Jev-negative and `P100–P199` = Jev-positive, and `id` is kept in the blinded file — annotators can infer the Jev decision. The annotation step is "(annotators)" in §10 with no script, model name, prompt wrapper or temperature; `analysis.py --h4-validated yes|no` is a human-set flag rather than a mechanical reading of `validate.py score`. `cannot_tell` consensus is counted as a Jev false positive (`validate.py score`) but the prereg does not say so. *Fix:* assign IDs after shuffling; add an annotator script with pinned models (different family from Jev) and record it in §10; have `analysis.py` consume the score JSON and apply G4/G5 thresholds; preregister `cannot_tell` handling; LLM annotators are acceptable if named and frozen.

**4. Gate/construct numbers are wrong and artefacts are stale.** `gates.py:26` counts `nondev` in `reach` although `funnel.json` already includes nondev rows in `ok` (caddy: 354+52+3+1+3+1+4 = 418 = fetched), so G1 denominators are inflated (axum "reached 694", actual 581; DESIGN-NOTES says 594). `constructs.py` floor share uses NaN rows as non-floor (34.75 %) whereas G3 over non-missing rows is 38.15 % (`gates.json`); DESIGN-NOTES §3 reports the wrong 35 %. `collect.py` and `data/pr-caddy.jsonl.gz` are newer than `panel.csv.gz`, `panel-final.csv.gz` and `funnel.json`, so the panel is not derived from the current script. *Fix:* correct both denominators, re-run the whole pipeline from the frozen scripts, regenerate DESIGN-NOTES numbers and digests.

## Must-fix

**5. Preregistration contradictions with itself or the code.** (a) §3.2 "all measured at/before S; no post-exposure variable" — churn, files, `frac_new`, task type and merge quarter are realized-change properties (as §6 admits). (b) §4 "no ridge shrinkage on the effect" vs T5 ridge 1e-2 on every non-intercept coefficient (`analysis.py logit`). (c) §3.3 `y_incomplete_explicit` "(no model)" vs §8(e)/`sensitivity.py:40` fitting T5 on it. (d) §5 says on G5 failure H4 is reported with the explicit variant only, but `analysis.py` still fits T5 on unvalidated `y_incomplete` and keeps its p in Holm. (e) `analysis.py` docstring describes a pairs-cluster bootstrap; the code is a jackknife. *Fix:* reconcile text and code; no discretion left.

**6. Power verification on a different scale/sample.** `power.py:38-40` standardises on all rows with D zero-imputed; `analysis.estimate` standardises per-test complete cases. `mean_est_at_mde` for T2 is 0.0586 vs planted 0.0502 (+17 %); T3 power at its "MDE80" is 0.65 (MC ±0.07). T5 adequacy (0.199 ≤ 0.20) is inside MC error. *Fix:* plant on each test's own sample/scale; report MC intervals; preregister the tie rule for marginal adequacy (e.g. upper MC bound ≤ SESOI) — otherwise T5 cannot receive an `equivalent` verdict.

**7. Jackknife bookkeeping.** `analyse()` uses one global G=480 and t(G−1) for every test although django's clusters carry no T1–T4 variation, and `v = v[np.isfinite(v)]` silently drops failed replicates. *Fix:* per-test cluster count; fail loudly or preregister the replicate-failure rule.

**8. `decide()` adequacy bypass.** `mde.get(t, 0)` and `--power` optional ⇒ equivalence can be declared without adequacy evidence. *Fix:* require the power file; default to inadequate.

**9. SESOI (gap 4).** Only T1/T2 have a rationale; none for T3/T4 (relative dispersion) or T5 (OR 1.22). *Fix:* justify each scale (external evidence or Scout's decision use) before freezing.

**10. Follow-up filter diverges from §2.** `follow.py:48` excludes bots by `author_type` only (collect.py also uses the login list); `is_follow` uses `created ≥ merged` while §3.3 says "after". *Fix:* share one bot predicate; state the boundary.

**11. Rule compliance.** Prereg cites `docs/inertia-research.md §4`, not ledger IDs (AGENTS Ledgers §3 requires `R-NNN`/`H-…`). `evaluation/change-cost-v2/reviews/` does not exist (rule 2) — this report must be committed as `reviews/round-1.md` together with the distribution inspections already made (rule 3).

**12. Reproducibility.** `fetch_prs.py main()` recomputes pins from the clone on every run, so `pins.json` is mutable; `uv run --with …` has no version pins; the §10 `infisical run` commands do not match the script docstrings (must run from the `finance-planner` project — gap 6, acceptable if documented and authorised); no prompt/question hash is recorded for the Jev calls. *Fix:* consume `pins.json` as an input, lock dependency versions, record prompt digests and the key-injection procedure.

## Minor

**13.** `tests.py`: trailing-snapshot test checks existence not ≥365 d age; the area-deepening assertion cannot fail; no test for the login-list bot rule, `logit`, `rel_abs_resid`, `decide()` verdict branches or `finalize_panel` NaN rules. **14.** `validate.py` docstring says gates are in "section 8" (§5). **15.** Mixed eras (gap 5): acceptable as a stated threat; add an old/new-cohort split to sensitivity (d). **16.** H2 via in-sample residuals with median area size 5: T4's area absorption in stage 2 limits the leverage artefact; record as threat. **17.** Secrets handling is correct (presence check, header only, HTTP code logged); cross-project store is housekeeping.

## Checked and found correct
Stable-population D (same files, same paths); deletions counted in churn and F_S; snapshot = parent of first commit else base; co-change window `(S−365 d, S]` strictly before S; follow-up timing (created ≥ merge, merged ≤ +14 d, censoring 14 d before T_end); Jev prompts contain no predictor or outcome values; within-repo standardisation; Holm implementation; area FE absorbed in T2/T4 with repo FE omitted (no collinearity); jackknife refits every stage; permutation uses a derangement; null scenarios reject at nominal rates (FWER 4.0–7.5 %); P1 base-vs-constant > 0; no evidence of any model fitted to real predictor–outcome data (`gates.json` has no G3b; `power.py` uses outcome marginals only); critique → fix map covers every M/C item.

## Challenger synthesis
Adopted from the challenger: the blinding leak (3), the gate-denominator and floor-denominator errors (4), the power-scale mismatch (6), the prereg contradictions (5a–c), mutable pins (12). Rejected: "validate active time against independently measured effort" (no such ground truth exists; narrowing the claim plus issue 2 suffices), "H2 must use forecast errors" (conditional residual dispersion is preregistered and standard), and "multiway/network inference" (author-cluster sensitivity (f) is preregistered and adequate). The challenger rated gap 3 blocking for a different reason; I rate it blocking because of the H1/H2 conflation shown by the harness.
