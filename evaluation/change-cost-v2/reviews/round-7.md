## New issues (all count under the zero-issues rule)

**1. Nit — stale "consensus `None`" sentence contradicts the corrected consensus rule.** `PREREGISTRATION.md:168` (end of the G7 bullet): "An `unparsable` annotator answer is a disagreement (consensus `None`, counted as unresolved)". After the round-6 fix, `:149-150` and the code (`validate.py:183-187`, test `tests.py:291-295` item `e`) give consensus = C's label when A or B (or both) are `unparsable` and C is parsable; consensus is `None` only when C is missing or `unparsable`. `annotate.py:12` "counts as a disagreement / unresolved" has the same imprecision. *Fix:* `:168` → "An `unparsable` A or B answer is a disagreement (C adjudicates); the item is unresolved only if C is missing or `unparsable`" (or delete the parenthetical, since `:149-150` is now authoritative); `annotate.py:12` → "counts as a disagreement; unresolved if C cannot resolve it". (Council and challenger independently.)

**2. Minor — partner selection order in the preregistration differs from `collect.py`.** `PREREGISTRATION.md:65-66`: "partner `g` qualifies if `n(f,g) ≥ 3` and `n(f,g)/n(f) ≥ 0.3` (top 10 partners per file). A qualifying partner **absent from the PR** and existing at `S` counts as *expected-but-absent*" — i.e. rank → truncate to 10 → filter absent; the ranking key is not stated. Code `collect.py:210-211`: `sorted((… if n >= SUPPORT_MIN and n / nf >= CONF_MIN and g not in in_pr), key=(-conf, -n, path))[:TOP_PARTNERS]` — i.e. filter absent → rank by confidence, support, path → truncate to 10; existence at `S` checked afterwards (`:220-223`). The two definitions differ whenever a file has > 10 qualifying partners and some of the strongest are touched by the PR: the implemented rule can count an 11th-ranked absent partner, the preregistered rule cannot. `n_hidden`/`n_partner_abs` (T5 predictor and control) and the `kind="partner"` follow-up candidates (`follow.py:66,71-75`) depend on it. Not anti-conservative in an obvious direction, and not previously raised in rounds 1–6 (grep of `reviews/` for `in_pr`/`top 10`/ranking: none). *Required fix (choose one, without looking at outcomes):* (A, recommended) amend §3.1 to the implemented definition — "among co-change partners not touched by the PR, `g` qualifies if `n(f,g) ≥ 3` and `n(f,g)/n(f) ≥ 0.3`; the 10 strongest per file (confidence `n(f,g)/n(f)` desc, then `n(f,g)` desc, then path) are kept; those existing at `S` are expected-but-absent" — `data/`, `candidates.jsonl.gz`, `labels.jsonl`, panels stay frozen; or (B) change `collect.py` to the preregistered order, which forces re-collection, `follow.py`, 60k Jev pair calls and every downstream artefact — disproportionate for a definitional choice between two equally defensible exposures. A synthetic > 10-partner fixture in `tests.py` is recommended, not required, under (A). (Challenger; verified.)
