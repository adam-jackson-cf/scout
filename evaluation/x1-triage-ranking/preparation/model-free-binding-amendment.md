The recorded unprivileged `eslogger` probe failed with `ES_NEW_CLIENT_RESULT_ERR_NOT_PRIVILEGED`; it was not a workable unprivileged observer. This amendment does **not** attribute the change to a failed nesting probe, claim all macOS nesting is impossible, or suppress Scout's existing analyzer sandbox. There is no outer experiment sandbox. ## Four proof layers

1. **Actual effective configuration, before scanners.** Resolve all parent/head configurations before starting any fixture scanner. Emit a faithful credential-free representation of the actual `engine.Config` and `engine.Options` passed to `Assess`, alongside original/frozen policy. The bound call must have no opted-in model lanes, decisions off, association nil/off, heuristic map source, unauthorized contextual and Clawpatch egress, absent ranking and no PR-metadata-fetch path. Assert those values before execution, then require byte-identical records during execution. Do not mistake a working-directory policy file or intended settings for the call's resolved inputs. The reference has its own explicitly absent stages; it never calls `Assess` or loads the override.
2. **Actual engine lane evidence.** Preserve and assert the engine's returned lane health, not merely policy. Contextual/Clawpatch-review must be skipped; planned feature/review coverage must be `skipped (not opted in)`. Association and association-fallback must report disabled; the model-CLI/decision-egress lane universe must be complete and unique. No lane marked ran/reused/blocked/failed can count as disabled. Jev ranking is structurally absent; decisions policy is off. A no-input skipped report is permitted only alongside the actual empty opt-in configuration and complete coverage/job checks. The scanner-only reference reports structural absence, not invented engine execution.
3. **Key/CLI impossibility guard.** Refuse if `OPENROUTER_API_KEY` is present at entry or launch, even with an empty value. Record only the presence boolean. Construct a private allowlisted environment/HOME/XDG/TMPDIR; inherit no credentials, model-home configuration or caller `CLAWPATCH_*` overrides. Pinned logging-and-failing `claude`/`codex` stand-ins occupy the first PATH directory and every supported executable override. `CLAWPATCH_CLAUDE_BIN` names the Claude stand-in. The actual pinned Codex provider uses literal `codex` on PATH and has **no `CLAWPATCH_CODEX_BIN` support**; its real `CLAWPATCH_CODEX_SANDBOX` is set to `read-only`, never `bypass`/`none`, and other caller `CLAWPATCH_CODEX_*` values are absent. Do not fabricate an unsupported override. Bound/reference logs must be empty; they are **stand-in attempt logs**, not global process logs.
4. **Positive control of the very same interlock.** Only on the synthetic fixture, leave the binding deliberately unapplied and retain the enabled original lanes. Exercise parent/Claude and head/Codex using no real CLI and no key. Require real stand-in records with executable/argv/PID and the pinned stand-in's fixed nonzero failure, expected production-provider argv and rejection by the same bound predicate. A fabricated JSON approval, prefilled attempts list, disabled-provider refusal before any attempt, or a successful empty log is not a control. Resolution-only runs must remain attempt-free. Django binds the already-passing synthetic receipt instead of enabling any Django model stage.

### What the proof answers, and what it does not

For **whether the audited Scout path could involve a model under these actual inputs**, these layers answer at least as well as an argv observer within the trust assumptions below: configuration/source gates exclude known in-process HTTP and CLI paths; returned lane/coverage rows attest which engine paths ran; and the enabled control demonstrates detector liveness **only for Scout's contextual seam**. Clawpatch review is blocked before provider spawn. Its own Claude/Codex provider routes are configured and statically checked, not exercised by this control: exclusion rests on empty opt-in lanes, false egress authorization and heuristic mapping with a null provider (layers 1–2), with stand-ins as defense in depth. Process-start observation alone would not establish absence of in-process HTTP or that intended policy was applied. This is not a universal replacement for process observation.

**Residual limitations:** pinned scanner binaries are trusted not to contain hidden model calls, backed by the hash-pinned installed closure and Scout's fail-closed analyzer network sandbox, **not observation**. That sandbox rebuilds PATH, so the controller stand-ins do **not** reach sandboxed scanner descendants; the sandbox is their guard. Separately, the **frontend, unsandboxed Node/Clawpatch dependency tree and its `git`/`go list` children have network available**. Their model-freeness rests on the cited non-transitive source audit, hash-pinned closure and configured stand-ins, not the analyzer sandbox. Unlike v1, v2 does not globally observe unexpected descendants or absolute-path model launches. The positive control establishes no Clawpatch-provider or scanner-descendant detector liveness. Empty logs alone are insufficient, and pinned software/OS/hardware compromise is not excluded.
