## 2. Rulings on the departures and the open items

Departures of PREREGISTRATION §14 item 15 and the choices of `reviews/round-3-response.md`:

1. **(a) `excerpt_lines` per re-scored unit row + the header's `input_sha256`, instead of a header field: accepted, conditional on R4-06.** The Go header's `input_sha256` is the SHA-256 of the `-in` file bytes (`jev/main.go:678-683,855`), so the chain header → `jev-v7/units.jsonl` → per-row `excerpt_lines` closes without a Go change **only if the consumer compares that digest**; `tune._check_v7_scores` reads the rows but never compares `h["input_sha256"]` with the file (`tune.py:145-156`; the comment at `:152` asserts a binding no code checks). No lawful path rewrites the file (`write_jsonl_new` opens with `"x"`, `x2d.py:408-411`; `run.sh:247-249` creates it only when absent), hence minor, but a self-declared field is not the binding the council asked for.
2. **(b) Re-render route, `excerpt_lines` stays in the menu: accepted** (the council's recommendation; `rerender_units` uses the same member text and representative rule as `make_unit`).
3. **(c) `p3_inside_min` as a report line with no threshold: accepted** — no threshold on the verdict; the disclosure and the round-0 acknowledgement are R4-03.
4. **(d) `C ≤ 1`: accepted** (the council's own prescription).
5. **(e) `p2_unmeasured: accepted` enforced when P2 is UNMEASURED: accepted together with R4-04.** As implemented the only value that unlocks round 1 is `accepted`, whatever the counts show; after R4-04 an already-decisive failure is FAIL and the line rules on a genuinely thin denominator only.
6. **(f) Round-0 R3-03 scope = D ∪ P plus the non-P2 controls that were labelled or attempted: rejected → R4-07.** A control the cap never reached has neither a label row nor a call row (round-3 accepted "no call row for a never-started capped case"), so it leaves the required set silently, contradicting `gold.py:309`'s own docstring ("never silently absent").
7. **R3-12 for every r ≥ 1: not a departure** (the fix text said so).

Open item, the low inside-positive cells (**ruling: disclose to the user before any spend; acknowledge at round 0; no new verdict gate**). The cells are report-only by the round-3 ruling and stay so. But they are not a minor operating detail: under the model as built (positives outside the 91 clusters, no abstention) the pilot says GO 84 % of the time at (p_J, p_B2) = (0.95, 0.80); with the ≈ 10 gold-`none` positives inside the 91 clusters it is 58 %; if Jev is also unresolved on 5 % / 10 % of clusters it is 33 % / 13 % (`PREREGISTRATION.md:138`). The mechanism is the rule itself, not noise: an unresolved answer is never correct (`analysis_x2d.py:145-147`), so Jev's end-to-end correct share is 0.95·(1 − a) and its expected gain over B2 is +0.15 / +0.1025 / +0.055 against the +0.10 **point** bar; the zero-abstention cell is held down by `P_new ≥ 0.80` on ≈ 10 positives with ≈ 2 expected false `none`s among 81 covered clusters [INFERENCE, both peers' arithmetic reproduces the cells]. Gain and `P_new` / `R_new` are point conditions (`analysis_x2d.py:338-345`), so the shortfall is **NO-GO**, not INCONCLUSIVE, and HD6 would move to `not-supported` for a reason unrelated to whether Jev's answers are right. Today the user is asked only when the proxy is < 10 or `p3_real_structure` < 0.80 (`x2d.py:350-354`); the binding cell is 0.84, so the question would never be put. Unresolved answers are structural here: a tuned `t_choice` (F0.5 rewards abstaining, §9 `:126`), the 20 % permutation flip with disagreement → unresolved (§7), and `t_cov`. Hence R4-03. The council does **not** turn this into a verdict gate (challenger's point, adopted) and does not amend the GO rule on the user's behalf: counting abstention as error is the preregistered cost model; whether the user wants to spend on a rule that mostly fires only when Jev rarely abstains, or wants a revised rule (e.g. gain and `R_assign` over resolved clusters with an unresolved-rate minimum beside them, a new preregistration revision and council round), is the user's decision and is escalated as a sign-off condition below.

### R4-13 (major) — the resolved-cluster GO rule: exact specification

Vocabulary. The **GO population** is unchanged (scored, non-control, no `core_gate`, pooled over rounds 8–10). A cluster is **resolved** when the primary arm's composed output is `assigned` or `none`; it is **abstained** when the output is `unresolved` for **any** reason (`below_t_cov`/`below_t_choice`, `permutation_disagreement`, `failure` — a cost stop or a missing row can never hide an error). B2's own `unresolved` (a B0/B2 tie) stays what it is today: a measured wrong answer for B2 (`score_outcome`, `analysis_x2d.py:145-147`); B2 never abstains in this rule's sense.
