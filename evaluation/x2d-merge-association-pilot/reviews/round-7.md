## 2. Rulings

1. **R7-01 severity.** The challenger rated the HD6 clause **major** (§14 maps GO to `supported` for the hypothesis as worded). The lead lowers it to **minor**: the rule, the code, `thresholds.json` and §9 row h agree with each other and with the validation (the e2e near-null, gaming and honest-10 % worlds, `validate.py:3303-3344`); no verdict changes; the defect is that the hypothesis sentence and the §14 parenthesis describe a different quantity from the one h computes, which must be exact in the ledger before HD6 moves to `preregistered`. Both peers found it independently; the lead had verified R5-06 / R6-01 as prescribed and missed it (it is the council's own round-6 text). The challenger's alternative — make h score raw answers on every cluster — is rejected: it changes the guard, its operating characteristics and the validation for no gain (the composed answer is what the product emits on a resolved cluster; the raw guess is a stand-in only where there is no composed answer).
2. **Pooled `unmeasured` double count (challenger C7-02, peer note): a note, not an issue.** `_planted_new_from_rounds` sums `trap_gold + trap_arm` (`analysis_x2d.py:1459-1460`), so one trap lacking both gold and an arm row would count twice. An absent arm row is unreachable live: `compose` writes `unresolved: failure` for every unit with a missing request, and `unresolved_block`'s contract says so (`:373-374`); the `missing` kind refuses earlier. No code change before sign-off; optional hardening recorded below for the design round.
3. **The peer's R7-04 (the §11 "95 % bound > 0 in ≤ 0.10 of pilots" sentence) is adopted and folded into R7-03 (c).** `power_sim` computes the bound only in pilots where every other condition passes (`README.md:64`; `power_sim.py:199-212`), so the cells measure P(GO) ≤ P(h), not the guard's marginal size; the sentence overstates what the run verifies, in a paragraph that calls itself "[INFERENCE …, which the power run verifies]".
4. **Below the bar (notes, not issues):** the response table's `u` column holds the input parameter (0.0 for the own-error and B2-error modes, whose realised abstention is the error share); the δ-curve cell at (0.95, 0.80) shares P3-u05's RNG stream (the seed string omits the cell name, `power_sim.py:132`) and is not independent evidence; `README.md:69-71` and `PREREGISTRATION.md:233-234` describe superseded revisions as history, correctly marked.
