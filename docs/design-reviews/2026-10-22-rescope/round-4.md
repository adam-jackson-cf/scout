## 1. Verdict: 7 ISSUES (0 blocker, 0 major, 2 minor, 5 nit) — not signed off

**C7 split: sound.** Deferring the X1/X3/X4/X5/X10 estimator, split, interval, population, sample size and the interim sampler's strata, fractions and floor to each experiment's council-signed preregistration is consistent with `AGENTS.md` experiment rules 1–4: rule 1 (`:10-13`) reviews "the experiment design (preregistration) and its implementation (scripts, data collection, models)", so the sampler that collects the data is reviewed there; rule 3 (`:16-20`) fixes units, outcomes, estimators and decision rules in the preregistration, before any predictor–outcome relationship is computed; rule 4 (`:21-24`) places the planted-effect/null validation with the preregistered pipeline. Writing those mechanics into the design would have frozen them (rule 5) before the user's §D minimums exist and would make each estimator change a design round as well. Rule 3 is satisfied by the kept text: every Jev-versus-label line is `insufficient` or withheld until X1's preregistration is signed off (`:160,166,308,374`).

**Kept text (C7a + four §6 principles): self-consistent and sufficient for the Phase 2 `decisions` adapter.** Per ranking: version key over `{instructions, criteria, state_shape, option_order_rule, resolved_model_id}`, redacted request body with realised option order (`:153`); pinned model with mismatch → `incomplete` (`:154`); rank-formula and baseline versions with every `ranking` disclosure and every disposition (`:155`); full probabilities (`:162`); baseline stored for every finding (`:164`). Failure semantics (`:158`), lane health matching §3.4 (`:88,159`), cap and `partial (n/N)` (`:157`), Phase 2's `ranking: deterministic (fork)` (`:356`) are consistent. Durability: the Issue record carries "dispositions + audit, advisory annotations" (`:75`) and `issues.jsonl` is in the `state/v1` export (`:180`), so annotations and audit records have a durable home; bulky request bodies fall under "workflow artifacts hold bulky evidence" (`:180`).

**Carry-forward items that are design-level.** Two items in `round-3-response.md:24-25` are write-time data capture that no later preregistration can reconstruct, and the kept text does not pin them: (a) the property that makes "each audited unit's inclusion probability is stored with it" (`:160`) a *realised* probability (an independent per-unit draw) plus the sampler version under which it was drawn — issue 1; (b) the audit-view flag that §9.7 (`:308`) filters on but §6 (`:166`) does not record — issue 2. Everything else in the carry-forward (estimators, `k`, split, de-correlation, ITT vs exclusion, test-set reuse, X3/X4/X5/X10 populations and intervals, §9.7 non-response rules, Phase 5 replay) is analysis and correctly belongs to the preregistrations.
