## Judgement calls for the council

1. **What "onboarding" means in the code (council decision, `round-1.md` issue 1).** At commit `f7b480e` (`internal/engine/refresh.go:106-115,126,129`; the companion change's `Refresher.Run` keeps the same test) onboarding is `record.LastAgentRefreshAt == nil`, so *every* default-branch push or nightly run attempts the agent map until one succeeds (the trusted workflow runs the map step on `push` and, with `--event nightly --default-branch`, on `schedule`: `scout-guardian-trusted.yml:182-183`). An attempt can end `skipped` (no `codex` on `PATH`; `RefreshSkipped`, "pending kept"), `blocked` (source egress not authorized: `internal/clawpatch/client.go:210-213` returns `MapBlocked`, `refresh.go:147-152` leaves `LastAgentRefreshAt` unset, and the workflow adds `--allow-egress` only when `AUTHORIZE_EGRESS == 'true'`, `:170-172`; the dogfood caller passes `inputs.authorize-egress || false`, `scout-nightly.yml:52`, so a CI attempt is `skipped` where `codex` is not on `PATH` (decided first, `client.go:203-206`) and otherwise `blocked` unless the caller sets `authorize-egress`, which the documented caller (`docs/references/ci-integration.md:63`) does only from a `workflow_dispatch` input; a manual `--refresh` success also records `LastAgentRefreshAt`, `refresh.go:129,163`) or `incomplete`; each leaves onboarding open. The draft keeps this behaviour and writes it down (§4, §7.1, Appendix 21, REQ-13, R15, Phase 4). **Council decision:** retry-until-first-success is confirmed as *onboarding*, not an automatic remap: before the first success no agent map exists and no area is re-labelled, and a `skipped` attempt, or one `blocked` before invocation (egress or prerequisite checks, `client.go:207-216`), makes no model call. The alternatives, (a) attempt once per repository and (b) onboard only from `scout init` / a manual map, are rejected because they leave a repository that merely lacked `codex` or egress on its first run permanently un-onboarded without a manual step the design never names.
2. **R-042 and R-043 as separate ledger rows** (R-040/R-041 precedent: user direction and study are separate rows). Both are added in the adoption change set (Companion changes (a)).
3. **0.5 stays although nothing supports it.** The user directed it; the design keeps it tagged **[ASSUMPTION]**. X2b's axum result sits on a cliff at 0.50 → 0.55 (RESULTS §1, **[INFERENCE]**), and fastapi fails everywhere, so any change of 0.5 would be unsupported; no value is proposed.
4. **Hard parse error for `mapping.refresh.debounce`.** `internal/policy/policy.go:204,232` decode the policy with `KnownFields(true)`, so after the key's removal an existing `.scout/policy.yaml` that sets it fails to load ("invalid policy"). The draft follows the clean-cutover rule (no shim). The alternative, accepting and ignoring the key with a warning, is a shim.
5. **`scout map` CLI shape.** The draft keeps `--event push|nightly --default-branch` (the workflow's onboarding evaluation) and `--refresh`, and drops `--base`/`--head`; a dedicated `--onboard` flag is an alternative. The design text names neither, so the council need not decide it; the code change does.
6. **Appendix 1 is marked, not rewritten**, so the 2026-10-19 decision and its supersession stay legible; the Revision 2.5 paragraph (historical) gets one appended sentence rather than a rewrite.
