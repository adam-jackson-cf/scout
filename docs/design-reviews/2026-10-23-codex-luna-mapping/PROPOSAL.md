## Explicitly not changed

The later design round that sets the default needs X2b signed off and run under the experiment rules first (`AGENTS.md` design rule 3).
- **§5.1 row 9, §3.1 tree, R13, R14, §7.1, Appendix 15's labelling sessions (`claude -p` / `codex exec`).** They concern `contextual`, `clawpatch-review`, Jev labelling or the generic "no CLI" skip, none of which this revision changes.
- **The Revision 2.2 paragraph (historical).**
- **Status/progress claims** (header) and §10.2's workflow row. `CLAWPATCH_PROVIDER` and the provider option no longer affect the agent map (code-verified: `resolveMapProvider` ignores them), so a workflow setting `CLAWPATCH_PROVIDER=claude` for review still maps on codex.

1. **Smoke timings.** They come from the main agent's report and no signed-off evaluation file records them; the unsigned X2b draft repeats them as a time estimate (`evaluation/x2b-area-stability-luna/PREREGISTRATION.md` §2, "Time"); per the main agent they are kept here (Fact 3) as operational observations and not in the design text.

A silent ignore means a misconfigured provider value is not surfaced for mapping; the design states the ignore explicitly.
3. **Appendix item 20, R-040 and R-041.** A new Appendix item records the decision, matching how revisions 2.2/2.3 recorded user decisions. `docs/STATUS.md:162` says to "add the next free `R-NNN` (R-040) at that time" for the MOSS candidate, which is not a reservation; R-040 is used for this user direction and R-041 for X2 (cited for the first time by rev 2.5, ledger rule 1; precedent E1b, R-035), and the MOSS candidate takes the next free ID at adoption (STATUS line 162 edited then; see Companion change).
