# `.scout/policy.yaml`

Use this catalog when you need to change what Scout gates, who may override it, or which optional lanes are consented. Source: `internal/policy/policy.go`, `internal/policy/consent.go`, `internal/policy/mapping.go`.

The file is parsed strictly, so an unknown key is an error. Scout reads it from the **base ref** of a run, never from the working tree, so a pull request cannot loosen its own gate. Without the file, Scout uses the defaults: profile `report`, no activations, decisions and model-CLI lanes off (`policy.go` `Default`, `Load`).

`scout init --yes` writes the minimal file:

```yaml
profile: report
```

## Example

```yaml
profile: guardian
maintainers: [alice]
blocking:
  shadow: {min_days: 14, min_pr_runs: 5}
  checks:
    - id: guardrails.SUPPRESS.added.unscoped
      version: guardrails.SUPPRESS.added.unscoped@1
      activated_at: 2026-10-23
      evidence: {would_block: 6, warranted: 6, window_days: 14, pr_runs: 9}
```

## Notes

For eligible `security.secrets.<rule>` checks in the pinned Gitleaks pack, activation `version` is exactly:

```text
gitleaks-default-rules/8.30.1@sha256:e163e53b9e7e8a8511e77271e2b323ed057759542a6d988258afe3a1fa329caf
```

Do not use the binary version `8.30.1`. All eligible rules in this pack share this value; `generic-api-key` remains report-only. Exact-version equality is implemented; content binding is enforced only for bundled fingerprinted packs, so their rule-content digest changes reset activation without migration. ADR-011 requires the Gitleaks pack version segment to match the binary pin; spec-validation enforcement with a test and a clearer short-version diagnostic are pending a later PR. Today's code does not guarantee parser/logic-bump resets: Semgrep-backed action-ref has no binary version in its pack key, and Scout-native guardrails reset only when someone hand-bumps the `@N` constant, an unenforced convention. Both binding gaps require a later ADR.

- `scout init` is idempotent: it keeps existing activations and comments, and keeps an existing `profile` unless you pass `--profile`.
- Model-CLI lanes and Jev stay off for a repository without a committed policy, even if `SCOUT_MODEL_CLI` is set.
- `mapping.refresh` was removed in revision 2.6; a policy that still sets it (for example `mapping.refresh.debounce`) fails to parse because the decoder is strict.
- Fallback is optional and push-only, and requires separate `association-fallback` consent plus a logged-in Codex CLI. It handles only this run's Jev `none`, below-choice-threshold and permutation-disagreement outcomes, not Jev failures or caps. Missing consent or Codex does not stop Jev or alter the gate exit code. The prompt digest and configured fallback model participate in association staleness.
- The refresh guard is advisory: a measured rate strictly above its limit latches `catalogue-stale` until a successful agent refresh changes the recorded generation. Equality is healthy; unavailable rates are unmeasured, not zero. Catalogue edits alone do not reset it. The guard recommends `scout map --refresh` but never runs a map or changes association labels or gate exit codes.
- Guard keys reject unknown fields and scalar coercions: counts must be positive YAML integers, and limits must be finite YAML numbers in [0, 1], including explicit zero.
