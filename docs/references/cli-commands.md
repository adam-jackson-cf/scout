# Scout CLI commands

Use this catalog to find the right `scout` subcommand and its key flags. Run `scout <command> -h` for the full flag list. Source: `cmd/scout/main.go` and the `-h` output of a build of the current tree.

Every command accepts `--root` (repository root, default `.`), `--clawpatch` (absolute path to the pinned Clawpatch `dist/cli.js`; defaults to `SCOUT_CLAWPATCH_BINARY`) and `--json` (machine-readable output).

## Exit codes

| Code | Meaning                                                              | Source                                          |
| ---- | -------------------------------------------------------------------- | ----------------------------------------------- |
| `0`  | clean                                                                | `cmd/scout/main.go` exit-code constants, REQ-24 |
| `1`  | gated: an activated check found an `introduced` or `regressed` issue | same                                            |
| `2`  | incomplete: a required lane did not finish                           | same                                            |
| `3`  | unavailable: bad input, missing tool or refused operation            | same                                            |

When more than one applies, the highest code wins: 3 > 2 > 1 > 0. Under the `report` profile, findings never produce `1`.

## Notes

- `scout` with no arguments prints a usage line generated from the dispatch table in `cmd/scout/main.go`; an unknown command exits `3` and names the command.
- `diff --head` must be the checked-out `HEAD`; check out the branch before you run it.
- Without a reachable `scout/state` baseline, `diff` reports `comparison: recomputed` and rescans the base itself.
- Local state lives in `.scout/`: `state.sqlite`, `artifacts/`, `clawpatch/` and `policy.yaml`. Commit only `.scout/policy.yaml`; `scout init` says so in its `next` hint. This repository's `.gitignore` excludes all of `.scout/`.
- `assess --artifact` records each ingested artifact's provenance per snapshot, keyed by the artifact's bytes. Ingesting the same bytes again with the same kind, revision, source and revision match is a no-op. Ingesting the same bytes with a different kind, `--artifact-revision`, source or revision match is an error, and the assessment notes it instead of overwriting the stored provenance (`internal/state/ingested.go` `RecordIngestedArtifact`).
- `assess` wires the optional Jev association lane from the policy committed at `HEAD`: `mapping.association.enabled` defaults false, with `covered_score: 0.60` and `t_choice: 0.535`. Jev also requires decisions consent/egress acknowledgement and `OPENROUTER_API_KEY` supplied to the command. `--allow-egress` is not a replacement for that consent.
- For association, pass `--from <base> --to <head>` (also used by `--scope commit_range`), or run in a GitHub default-branch push with `GITHUB_EVENT_NAME=push` and `GITHUB_EVENT_PATH` containing its `before`/`after` range. An absent range is explicitly skipped. GitHub PR/fork payloads and non-default-branch pushes are ineligible; `assess --fork` explicitly disables association calls and `assess --no-egress` forbids association Jev egress. These flags do not change the existing finding-ranking configuration.
- Area IDs precede flags. Area commands make no model calls; mutations require a writable store. Acceptance survives map matching and prevents retirement. A completed agent map supersedes pending proposals and association records only when active area FileSets cover every surviving path at that revision; deleted paths do not block supersession.
- Area actions are exported in `state/v1/area_actions.jsonl` and restored with associations and areas. Differential assessment JSON includes complete pending payloads in `result.pendingAreas`; its bounded summary lists at most 8 pending IDs and their files, followed by `- … N more` when additional areas are omitted.
- `scout init --yes --model-cli codex --lane association-fallback` records separate fallback consent. Interactive onboarding discloses that bounded file excerpts, PR title/body and catalogue content go through Codex to OpenAI. Fallback always uses Codex even when `model_cli.provider` is `claude`; the provider selection still controls the other model-CLI lanes.
- `assess` passes that fallback consent and `mapping.association.fallback` settings to association. The optional, push-only fallback handles only this run's Jev none/below-choice-threshold/permutation-disagreement outcomes. Missing consent or Codex skips fallback without suppressing Jev or changing the gate exit code. Defaults are model `gpt-6.1-terra`, effort `high`, timeout `900s`, 40 decisions and 10 new pending areas per run; the two caps accept explicit zero. The exact prompt digest and fallback model are included in the association decision fingerprint.
- `readiness` and `assess` expose the advisory refresh guard as `associationGuard` in JSON, including the generation, decision-ordered merge window, rate numerators/denominators, measurement reasons, stale latch and recommendation. The window contains the trailing merges producing residual clusters in the current agent-refresh generation; pending-new-ineligible merges still occupy window slots. Fallback measures Jev none/unresolved clusters divided by all residual clusters in that window, whether or not fallback ran. It reports `insufficient_clusters` below the whole-window cluster minimum. Pending-new filters to eligible merges and reports `insufficient_clusters` below their cluster minimum, or `no_fallback_answers` when that minimum is met but no fallback-answered cluster exists. Defaults are a 20-merge window, a 20-cluster minimum for each rate's population, fallback limit 0.40 and pending-new limit 0.20; configure them under `mapping.association.guard` in [the policy reference](policy-file.md).
- A measured rate strictly exceeding either limit latches `catalogue-stale` and recommends `scout map --refresh`; equality does not trip the guard. Summaries show the diagnostic, and `assess` JSON `result.associations` annotates exported rows with `catalogue_stale`, even when the association lane is disabled. This is output only: stored rows, labels and gate exit codes are unchanged.
- The guard replays stored decisions for the recorded last successful agent refresh, so import/restore preserves historical trips even if the current window is healthy. Inherited-only or excluded-only merges do not consume its window. A skipped fallback run is ineligible for pending-new measurement. Only a successful agent refresh resets the latch; catalogue edits do not. No guard output automatically invokes `map`.

## Choice order-flip measurement

`scout decisions orderflip --question merge.which_area --units <file.jsonl> [--json]`
loads decisions consent and the exact model pin from the policy committed at
`HEAD`. It refuses without enabled decisions, egress acknowledgement or a Jev key.
As with the decisions lane, `--allow-egress` cannot replace committed consent.
No measurement is run by `assess`; this is an explicit, standalone measurement.

Each JSONL record is `{"id":"unique-unit-id","state":{...}}`. The bounded
association state must include `catalogue`: an array of
`{"id":"area-id","title":"...","summary":"...","sample_files":["path"]}`.
The command constructs `merge.which_area@v1` with `decisions.MergeWhichArea` for
each unit's catalogue (2–255 unique options), then uses the harness's deterministic
unit-id permutation and its reverse. It preflights every unit before making calls.
Only `merge.which_area` is supported; Noul questions have no option order.

JSON output uses the standard outcome envelope. Its `result` contains flip rate
(`null` if no units were measured), measured/unmeasured/flipped counts, maximum
probability shift, reported USD cost, per-unit rows and `question_versions` keyed
by unit ID (catalogues may differ). The aggregate `question_version` is empty:
there is no single catalogue-specific version for the whole input. A failed call
makes that unit unmeasured, never stable; reported billed costs are still included.
Missing billed costs remain unknown to the adapter and are not estimated.
Text output prints the aggregate summary; `--json` includes the per-unit rows.
The measurement asks twice per unit and is not a ranking run: ranking per-run
request and cost caps do not truncate this explicitly supplied measurement set.

### Pilot FastAPI rounds 8–10

The frozen pilot stores its catalogue in `noul_state`, not `choice_state`.
This throwaway conversion preserves that bounded state and the original case ID;
it writes only under `$TMPDIR` (falling back to `/tmp`), never under `evaluation/`.
Run from the Scout checkout. `CONSENT_ROOT` names a repository with enabled,
acknowledged decisions and an exact model pin committed at `HEAD` (set up with
`scout init --decisions --acknowledge-egress --yes`, then commit its policy).
This is a measurement command, not permission to run a new experiment without
the repository's required experiment sign-off.

```sh
source .tools/activate
export CONSENT_ROOT=/absolute/path/to/consented/repository
export ORDERFLIP_UNITS="$(mktemp "${TMPDIR:-/tmp}/scout-orderflip.XXXXXX")"
python3 - <<'PY'
import json
import os
from pathlib import Path

base = Path("evaluation/x2d-merge-association-pilot/data/postrun/rounds")
with open(os.environ["ORDERFLIP_UNITS"], "w") as out:
    for round_id in (8, 9, 10):
        with (base / str(round_id) / "states.window.jsonl").open() as source:
            for line in source:
                row = json.loads(line)
                out.write(json.dumps({"id": row["case_id"], "state": row["noul_state"]}) + "\n")
PY
infisical run --projectId 052b4c81-b9cc-4694-9019-d131ec3817cc --env dev --silent -- \
  go run ./cmd/scout decisions orderflip --root "$CONSENT_ROOT" \
  --question merge.which_area --units "$ORDERFLIP_UNITS" --json
```

## Planned shadow readiness (ADR-012; implementation pending)

Only this read-only interface is selected by [ADR-012](../adrs/2026-11-08-shadow-readiness-inputs/ADR.md); it is not shipped yet:

`scout readiness --shadow --check <id> [--version <exact>] [--as-of <RFC3339>] [--json]`

Read existing state without network/scanning/models/initialization. Apply REQ-78’s population, causal-supersession, provider-job-start, completeness and single query-wide visibility rules to default-version selection, in-scope attempts, representatives, links, vetoes, gaps and Days origin. Destination C at publication is the CAS-parent frontier, recomputed on retry; the same commit’s advance never makes its own facts/points late. REQ-78’s single predicate applies to facts and each gap point independently: coordinate≤as_of and, only if coordinate≤destination C at publication (late), stamp≤as_of; pending facts are invisible. Only points in (parent C, new C] require published normal gaps visible at the enabled frontier; late points≤parent C, including equality, never block advance. Supersession exclusion requires an identified superseding run of the pinned guardian lane for the same PR key, created (run created_at at its first attempt, never rerun-attempt time; a rerun attempt of an earlier-created run never qualifies) after the cancelled attempt’s job started and before that attempt’s cancellation, whose executed configuration verifiably equals the pinned protected-default configuration and evaluates cancel-in-progress=true for the same evaluated concurrency group as the cancelled run. Additionally require either a provider-recorded concurrency cause or no actor-initiated cancel recorded; the provider cause replaces only that last condition, never the run/configuration checks. If no qualifying run can be identified within both bounds, including when original run creation cannot be distinguished from rerun-attempt time, assess or gap the head, never exclude it; missing proof cannot certify readiness. Cancellation by another workflow or job, an unidentified canceller, or a PR-edited superseding run is assessed/gapped. Unknown cancellation cause is assessed/gapped, never excluded. Approval waiting has no started attempt; deadline-expired non-terminal attempts are point-gapped and later terminal facts are late. Every point ends its interval with exclusive boundaries. Default version is check pin of maximum (started_at, numeric attempt-ID tuple) visible in-scope attempt; tuple is (provider repository ID, run ID, run attempt, job ID), compared numerically field by field. Unverifiable ordering is unmeasured/exit 2. Default cutoff is C; known historical exact versions select cohorts.

Counting follows REQ-78: latest assessed exact-cohort representative supplies comparison/inspection/PRRuns and qualifying Days origin; event union uses all eligible assessed cohort links. UnknownAttribution counts comparison-none OR base-gap unknown once. Both cohort-wide zero-not_warranted/zero-Undecided sets include late/gapped evidence according to the single publication-visibility rule; no ready/provisional result bypasses either veto. Report all counts, prior-interval vetoes, late gaps by stamp, superseded history, inspection counts, distinctPRs and each distinct Scout/tool/catalogue/policy pin tuple with represented-observation count (non-additive for mixed pins). Use immutable latest frontier≤as_of for policy/minima.

Apply REQ-78’s lineage and history rules: lineage is the authenticated trusted publication chain (provider repository ID, state ref, genesis publication ID), on every published fact/row. Only proven same-lineage entire-published-history prefix, including post-C rows, is fast-forward; non-empty/no-C never qualifies vacuously. All other adopted chains need original/current-tip author authorization, action-ID deduplication and fresh successive stamps, one row/event/publication in original stamp/numeric-action order. Persist/export/import idempotent import-refusal records with action/event IDs, reason, lineage and CAS stamp. Each publication adding a new accepted/refused row reopens only its event to Undecided at stamp≤as_of; only an authorized destination verdict after its last such publication resolves it. Replay is no-op. Canonical dossier/dossier_digest uses a deterministic canonical encoding carrying a format version, retained for historical reproduction; unsupported encoding exits 3 rather than silently re-encoding. It covers exactly repository ID, resolved as_of, selector version and path-filter population, cohort, interval, immutable frontier, pins, protected policy revision/effective minima, counts/exclusions, triage at as_of and readiness/provisional reason. Counts include late gaps, prior-interval vetoes, superseded-not_warranted history, inspection counts, distinctPRs and each distinct Scout/tool/catalogue/policy pin tuple with represented-observation count (non-additive across mixed-pin attempts). A labelled live envelope outside the digest contains certification: current|refused|historical, reader time, reader-clock frontier age, installed mismatch, post-cutoff authorized history/late records and pending late facts/imported history. The dossier reason stays the result computed at as_of. Only current_window with certification=current can supply activation evidence. Current-window refusal triggers are exactly repository late records stamped>C; triage/history records stamped>C that change this exact cohort’s veto-event triage state, whether authorized verdicts or import-refusal records; and pending local late facts or imported history in the reader store. Normal started_at>C facts, frontiers and publication metadata do not trigger refusal. Every such refusal is certification=refused, unmeasured/exit 2 regardless of the computed result, clearing when C reaches the stamp (pending inputs must first publish). Evidence refusals including unproven completeness/time and unverifiable attempt ordering are exit 2; cross-lineage history instead computes the Undecided veto once visible. Explicit --as-of is certification=historical even at C, never activation evidence; it may share the refused current query’s digest. Explicit cutoff is historical_reproduction, default current_window; another policy is policy re-evaluation, never reproduction.

as_of≤C evaluates even when reader clock lags: computed ready/not is exit 0 unless current certification is refused under REQ-78, then unmeasured/exit 2 with certification=refused. Unmeasured/no store/no complete containing interval and all evidence refusals (unproven completeness/time, unverifiable attempt order, scoped pending/post-C inputs) exit 2. C<as_of≤reader now exits 2; as_of>max(C,reader now) exits 3. Invalid/unknown explicit version/storage/unsupported schema or canonical encoding exits 3 (v13 requires writable upgrade). Historical status cannot supply activation evidence, even with the same digest. Missing/local/legacy evidence never becomes computed zero.
