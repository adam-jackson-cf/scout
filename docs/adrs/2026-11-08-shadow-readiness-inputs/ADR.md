## Decision and scope

## Which observations count

1. Eligibility is the pinned guardian PR lane’s protected-default-branch trigger configuration (event types, branch/path filters), with no further content/label/author/outcome filter beyond that configuration; disclose path filters as a population limit. Selector means that configuration plus collector eligibility-logic version; changing either starts a new interval, while Scout/tool/catalogue/policy pin changes do not. Provider enumeration lists PR events with provider event_at on protected-default-base PRs, not runs; include forks/bots. Collector reassessments only add attempts to existing observations. Non-default base or B unreachable from protected default tip is disclosed not_assessed/non_default_base. Evidence is repository-qualified immutable authenticated CI scope, not PR assertions. PR/fork jobs are read-only; trusted writers append readiness facts/events/triage, never baseline content.
2. Persist PR key, H commit/tree, B, merge_base, assessed revision, baseline identity, pinned Scout/tool/catalogue/policy/check versions, provider started_at, terminal outcome, accounted-event IDs/times and would_block links. Each attempt durably names the provider PR event IDs/event_at values it accounts for. An assessed/comparison-none attempt accounts an event only with the same PR key, H commit equal to the provider event head SHA and started_at≥event_at. non_default_base and not_assessed records also name their event. A waiting event holds C back; record a gap containing event_at only when it will not be accounted (including collector non-start, deferral past its chosen deadline, closure/merge or approval waiting). A delay alone is not a gap. Missing head/binding evidence cannot certify accounting. Only provider-proven guardian non-assessment may be excluded: conflict with no merge result; pre-assessment cancellation meeting the supersession condition below, or provider-recorded system cancellation; or a provider-recorded skip from the pinned lane’s configuration. Supersession exclusion requires an identified superseding run of the pinned guardian lane for the same PR key, created (run created_at at its first attempt, never rerun-attempt time; a rerun attempt of an earlier-created run never qualifies) after the cancelled attempt’s job started and before that attempt’s cancellation, whose executed configuration verifiably equals the pinned protected-default configuration and evaluates cancel-in-progress=true for the same evaluated concurrency group as the cancelled run. Additionally require either a provider-recorded concurrency cause or no actor-initiated cancel recorded; the provider cause replaces only that last condition, never the run/configuration checks. If no qualifying run can be identified within both bounds, including when original run creation cannot be distinguished from rerun-attempt time, assess or gap the head, never exclude it; missing proof cannot certify readiness. Cancellation by another workflow or job, an unidentified canceller, or a PR-edited superseding run is assessed/gapped. Causes must be independent of outcome/content beyond the trigger configuration, labels, author and approval. Unknown causes, manual cancellations, skip-instruction non-runs and approval-pending forks are assessed or gapped, never assumed exclusions. Assess the pinned guardian merge-result-versus-B procedure. Authenticated assessment input/output failure is comparison-none, never exclusion; a collector unable to enumerate/attest the event records a gap.
3. Override inputs must equal the pinned guardian lane's inputs. Today that lane passes none; shadow must not infer overrides from PR labels/body. Adding overrides to both lanes is a separate design change. Non-conflicting merge-result equivalence is [ASSUMPTION] until demonstrated; the implementation must prove event/comparison parity, including PR text containing override markers.
4. **Clocks, frontier and late evidence.** C is the sealed provider-clock collection frontier. event_at is provider event time; started_at is provider job start, not run creation (approval waiting has no started attempt). C advances only within provider-attested complete event/attempt enumeration bounds minus implementation-justified consistency lag, never writer time: every eligible event≤t is accounted or gapped, and every attempt started≤t is terminal/published or discharged by a published point-gap record. At the collector’s chosen deadline a non-terminal attempt is point-gapped; later terminal facts follow the late lifecycle. Unproven completeness/time is unmeasured/exit 2. Immutable policy-bearing frontier records are keyed by strictly increasing C; sealed history is never rewritten. Destination C at publication means the frontier in that publication’s CAS parent, the same parent C used by the stamp formula, recomputed on retry; an advance in that commit never makes its own facts or points late. A fact is late when its started_at (attempt) or event_at (event) is ≤ destination C at publication; each gap point independently is late when point≤that C. Collection, merge and import preserve authenticated late attempts/links/events append-only, flagged late and stamped only by trusted publishing CAS; local late facts stay pending until then. One visibility predicate governs every query, including default version, in-scope attempts, representative, links, vetoes, gaps and Days origin: facts and gap points require their provider coordinate≤as_of and, only if late, stamp≤as_of; pending facts are never visible. Links inherit their facts’ visibility. A point-gap record discharges only its covered validated obligations: points are started_at and every accounted event_at for an attempt, or event_at for an unaccounted event. Each point ends the containing interval: previous interval ends strictly before it, next starts strictly after it, and attempts at it belong to no interval. For points in (parent C, new C], advancement requires a published normal gap, visible at every cutoff the advance permits; points≤parent C (including equality) are late and never block advancement. Late points and late facts use only the same visibility predicate; earlier dossiers stay identical. CAS assigns recorded_at=max(publishing-run provider start, parent C+1ms, parent maximum publication recorded_at+1ms), recomputed on retry; unavailable/unreliable provider time refuses publication. Import follows the history rule below. Advance C at triage publication and periodic trusted reconcile when bounds permit; cadence must let quiet repositories pass every stamp. A stamping publication reaches its stamp only if its attested bound minus lag permits, otherwise a later reconcile does. Report late gaps by stamp. Current certification uses only the scoped refusal rule below, not every publication.
5. For exact (check_id, rule_version), represented observations use the complete interval containing as_of, attempts pinned to that version and interval.start≤started_at≤as_of. Deduplicate (PR key, H tree OID, merge-base); the maximum (started_at, numeric attempt-ID tuple) terminal assessed attempt is representative. Reruns/no-op trees cannot inflate exposure; distinct trees of one PR count separately [ASSUMPTION], with distinctPRs disclosed. Event evidence unions all assessed cohort attempts. Both zero-not_warranted and zero-Undecided predicates include every authenticated linked CI event of this repository/exact cohort, whatever its interval, gap or late status, using triage at as_of. Apply the single visibility predicate above throughout. All ready results, including provisional, require both zeroes. Report prior-interval not_warranted/undecided. Days/PRRuns/TotalRuns/UnknownAttribution/WouldBlock/Warranted remain interval-scoped; point gaps end intervals, never puncture exposure.
6. TotalRuns counts represented assessed observations. UnknownAttribution counts an observation once if its representative has comparison-none OR any finding became unknown because of a base-family gap; no other unknown category enters this bound. Equality at 10% passes. Comparability, selected-check inspection status and PRRuns membership come only from each observation’s representative at as_of (latest terminal assessed cohort attempt in interval, ordered by started_at then the numeric attempt-ID tuple). PRRuns counts only representatives with fully inspected comparable base; full inspection means all eligible units completed without blocked/failed/limited coverage and comparable base inspection (completed inline comparison for guardrails). No eligible units is not_applicable; other incomplete coverage is not_inspected. Report inspected/not_inspected/not_applicable counts. Days = floor((as_of−origin)/24h) on the provider clock; origin is earliest representative started_at among represented observations whose representative is comparable and selected-check inspected. No origin means unmeasured. An in-scope attempt is this repository’s CI eligible attempt on protected default base (excluding non_default_base), with a recorded pin, of any terminal outcome. Attempt ID means (provider repository ID, run ID, run attempt, job ID), compared numerically field by field wherever it breaks a tie; unavailable/unverifiable ordering refuses readiness, never uses a text fallback.
7. Eligible links connect cohort attempts to events of that check and exact rule version. In-window event evidence is the distinct union of those links across **all** assessed attempts of each represented observation, not just its representative. For new shadow IDs, base=merge_base(B,H), head=H tree OID; canonical ID inputs are (base, head, check, issue, rule_version). B and assessed merge result are provenance, not event identity. Advancing B within one observation must link the existing event. Never overwrite rule_version. No later empty rerun can erase a not-warranted event.

## Who may triage, and historical cutoffs

Only the provider-authenticated author of a triage action may supply its verdict/reason, and that author must still be authorized by maintainers/CODEOWNERS at the **current protected default-branch tip when publishing** (REQ-23 exact-name rules). Record that policy revision. Reject/log non-maintainers, revoked maintainers, non-default-branch writer execution and source not reachable from the protected default tip. A different actor rerunning an action cannot authorize its original author's inputs; original and executing actors must match. A logical action has one stable repository-qualified ID (for a GitHub dispatch, repository ID plus dispatch run ID); replay publishes nothing and cannot overtake a newer verdict. These are authorization/idempotence invariants, not a selected dispatch interface. Integrity against collaborators who can create write-token workflows still relies on the existing scout/state ruleset (REQ-161).

Append immutable would_block_triage rows with action ID, event ID, verdict, actor, reason, policy revision, provenance time, lineage and recorded_at under the clocks/frontier rule. At most one row per event per publication; latest authorized visible row by recorded_at then numeric action ID is current, none means Undecided. Lineage is the trusted publication chain, identified at least by provider repository ID, state ref and genesis publication ID, recorded on every published fact and row; authenticated chain ancestry must be proved, not inferred from a claimed ID. Fast-forward requires the same lineage and the destination’s entire published history (all frontiers, stamped facts and rows, including post-C ones) as an identical prefix of the import. A non-empty destination never qualifies vacuously. Only a proven fast-forward adopts original trusted stamps, including in sealed local stores, exactly as fresh restore; every other import, including missing/unverifiable lineage, follows the cross-lineage rule. Cross-lineage rows are action-ID deduplicated and published successively per event in original (recorded_at, numeric action ID) order, retaining provenance and receiving fresh destination CAS stamps. Every adopted row outside strict fast-forward requires verifiable original authorization and its original author’s current-tip authorization under the rule above. Refuse/log failures and persist an immutable import-refusal record (action ID, event ID, reason, lineage, CAS recorded_at), idempotent by action ID and exported/imported under these same rules. An import publication adding at least one new accepted or refused row for an event makes only that event Undecided once the publication’s stamp≤as_of. Only an authorized destination verdict stamped after its last such publication resolves it; a verdict between import publications cannot resolve subsequent rows. A replay adds nothing and reopens nothing. Both query modes filter history/refusal records by stamp≤as_of; default is as_of=C. Post-C publications never alter canonical dossiers≤C. Dispatch time is provenance only. Report visible superseded not_warranted history; frontier age and post-cutoff records are live diagnostics.

Only computed complete inputs reach ShadowReady. Retain the 14-day/5-observation defaults, maintainer/per-repository clauses and per-repository auto-demotion verbatim, and add the declared cohort-wide zero-not_warranted and zero-Undecided conditions across gaps. Zero-Undecided is required before any ready result, including the existing rare-security zero-in-window-events provisional exception; its reason states inspected count. Readiness never auto-activates.

## Read-only readiness interface

`scout readiness --shadow --check <id> [--version <exact>] [--as-of <RFC3339>] [--json]` reads state without network/scanning/models/initialization. Default version is check pin of maximum (started_at, numeric attempt-ID tuple) visible in-scope attempt; exact historical cohorts are supported. Default cutoff C gives current_window; explicit cutoff gives historical_reproduction. as_of≤C evaluates; C<as_of≤reader now exits 2; as_of>max(C,reader now) exits 3. Computed ready/not exits 0, unmeasured/no store/no complete containing interval exits 2, invalid/unknown explicit version/storage/unsupported schema/encoding exits 3. Use minima from immutable latest frontier≤as_of; other-policy evaluation is labelled policy re-evaluation. Canonical dossier/dossier_digest uses a deterministic canonical encoding carrying a format version, retained for historical reproduction; unsupported encoding exits 3 rather than silently re-encoding. It covers exactly repository ID, resolved as_of, selector version and path-filter population, cohort, interval, immutable frontier, pins, protected policy revision/effective minima, counts/exclusions, triage at as_of and readiness/provisional reason. Counts include late gaps, prior-interval vetoes, superseded-not_warranted history, inspection counts, distinctPRs and each distinct Scout/tool/catalogue/policy pin tuple with represented-observation count (non-additive across mixed-pin attempts). A labelled live envelope outside the digest contains certification: current|refused|historical, reader time, reader-clock frontier age, installed mismatch, post-cutoff authorized history/late records and pending late facts/imported history. The dossier reason stays the result computed at as_of. Only current_window with certification=current can supply activation evidence. Current-window refusal triggers are exactly repository late records stamped>C; triage/history records stamped>C that change this exact cohort’s veto-event triage state, whether authorized verdicts or import-refusal records; and pending local late facts or imported history in the reader store. Normal started_at>C facts, frontiers and publication metadata do not trigger refusal. Every such refusal is certification=refused, unmeasured/exit 2 regardless of the computed result, clearing when C reaches the stamp (pending inputs must first publish). Evidence refusals including unproven completeness/time and unverifiable attempt ordering are exit 2; cross-lineage history instead computes the Undecided veto once visible. Explicit --as-of is certification=historical even at C, never activation evidence; it may share the refused current query’s digest. Existing matrix behavior remains except query-only v13 refusal until writable upgrade.

## Implementation acceptance invariants

- R5-01: a proposed trigger/input/workflow/permission/key/release or governed-requirement change cannot merge without an adopted zero-issue wiring ADR meeting this contract; wiring unchanged within existing requirements needs no such ADR.
- R5-02/R6-01/08: omitted failing eligible PR prevents certification; collector-skipped unstarted event is a gap containing event_at, never an exclusion. Approval-pending fork is assessed or gapped, never excluded; non-default/unreachable base is disclosed non_default_base. Trigger/path-filter population and selector version are explicit. H2-only collection cannot account H1’s event: E1 holds C or is gapped. Manual pre-assessment cancellation, including cancellation followed by a later push, and [skip ci] are assessed or gapped. Approval-waiting forks have no started attempt and cannot hold C; a non-terminal job at deadline is point-gapped. Advance C past its started_at before publishing terminal facts, then assert they are late and invisible before their stamp. With C≥terminal stamp and no refusal trigger, assert the late terminal attempt and its linked would_block event are visible, yielding computed exit 0 not-ready/Undecided, paired with an otherwise identical ready control without the late terminal facts. With pinned cancel-in-progress=false, H2 pushed before H1 manual cancel and no canceller recorded still assesses/gaps H1. R1=true, R2 executed configuration=false (PR edit or base change between runs), then manual cancel with no recorded canceller: H1 is assessed/gapped; also assert this for unverifiable R2 configuration. Keep the all-false case. PR-added workflow job joins guardian group with cancel-in-progress=true, cancels H1 before assessment with provider cause and no H2: H1 is assessed/gapped. With pinned=false, H2 PR-edits R2 executed configuration to true in the same group and cancels R1 before assessment: H1 is assessed/gapped both with no recorded canceller and, separately, with provider-recorded concurrency cause. Retain the existing all-false, R1-true/R2-false and unverifiable-R2 fixtures. Supersession-window fixtures (all other exclusion conditions satisfied): (1) pinned=true, unedited configuration, no actor recorded/no provider cause; R1 is cancelled before assessment and H2’s R2 is created only after that cancellation: assess/gap H1. (2) Pinned=true; R2 legitimately supersedes R1, then a PR-added job cancels R2 before assessment with provider cause and no H3: assess/gap H2, never accept older R1 as its superseder. (3) Repeat (2) with R2 manually cancelled, no actor recorded and no provider cause: assess/gap H2. These isolate the upper bound and both lower-bound evidence paths; keep every existing fixture. (4) Pinned=true, unedited configuration; R1 on H1 is terminal; R2 on H2 has started; a maintainer reruns R1 and the rerun attempt cancels R2 before assessment; no H3. Once with provider concurrency cause and once with no actor recorded/no provider cause: assess/gap H2, never accept R1’s rerun attempt as its superseder.

Retain attested-bound refusal, lagged-listing recovery and pre-C export merge/import historical stability. With parent C<point=new C<stamp, new-C has no complete containing interval (unmeasured/exit 2); a later cutoff after the point selects the next interval.
