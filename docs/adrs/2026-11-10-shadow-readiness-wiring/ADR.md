# ADR-015: Wire non-certifying shadow collection and authenticated triage

- **Status:** accepted-form; effective only on this folder's explicit final zero-issue council round
- **Deciders:** agent-decided under owner delegation (R-064)
- **Decided:** 2026-11-10; **sources:** R-064, R-070, R-077, R-100–R-103
- **Delivery:** design only; no Go or workflow changes; owner review pending in editable trackers.

## Decision and limits

Select non-certifying collection/triage wiring left open by ADR-012. The certifying PR-event source remains unselected: production shadow readiness stays unmeasured/exit 2 until a later adopted wiring ADR proves a complete source. This does not narrow ADR-012 or close its implementation acceptance. Missing authenticated complete event/started-attempt bounds or provider time never means ready. No pre-cutover coverage is certified. No external service, App, secret, population exclusion or weakened evidence rule is adopted.

The normative machine copy of W1–W6 is [wiring-contract.json](wiring-contract.json). Both prose and contract are signed; any disagreement is a gate failure, not implementation discretion.

### W1 — Dispatch source, transport and authorization

Extend `scout-nightly.yml` workflow_dispatch with `shadow-operation` (choice `reconcile|triage|start`, default `reconcile`), `shadow-event` (string, default empty), `shadow-verdict` (choice `none|warranted|not_warranted|undecided`, default `none`), and `shadow-reason` (string, default empty). In `scout-guardian-trusted.yml` workflow_call these four inputs are strings with the same defaults; forward operation/verdict using the default fallbacks and event/reason without transformation. The binary revalidates all values. Non-dispatch events treat all four as absent/reconcile. Existing full/refresh-map/authorize-egress meanings remain unchanged for reconcile. Triage/start require all three booleans false. Reconcile requires verdict=none and empty event/reason; triage requires an existing persisted CI event ID with its canonical grammar and verdict other than none; start requires empty event and verdict=none. Triage/start reason is 1–1,000 UTF-8 bytes without control characters. Explicit undecided is an append-only verdict retraction under ADR-012's latest-visible-row rule. Pass data via step env and argument arrays, never interpolate it into executable shell.

Authority is the GitHub-issued executing-attempt context, read by the trusted released binary through step-level env before any assessed code or scanners. Bind inputs, event_name, actor_id, triggering_actor, run_id, run_attempt, repository_id, ref, sha and workflow_ref. REST GET run and GET run attempt must corroborate workflow_dispatch, numeric repository ID, default head_branch, head_sha, caller path, original numeric actor ID and this attempt's triggering numeric actor ID. Inputs are **not REST-verifiable**: integrity rests on the trusted context, ordering and GitHub's documented rerun reuse of original inputs (R-102). Only checkout, setup-node, release-tag install/toolchain scripts and safe state restore may precede triage/start. Never take authority from scanner artifacts or local actor/trusted flags.

Logical action=(numeric repository ID, run ID), not run_attempt. Require original numeric actor ID=executing numeric actor ID. Resolve the current login from that numeric identity on every CAS retry and apply REQ-23 exact-name maintainer/CODEOWNERS matching at the current protected default tip; record ID, login used and policy revision. Prove protected-default execution/source ancestry and refuse/log missing proof, mismatch or revoked/nonmaintainer author. The first terminal accepted or immutable refusal record for a logical action is final; later attempts publish nothing. A run that published nothing may be rerun by the same actor with fresh authorization/stamps. At most one row/event/publication; replay cannot overtake a newer verdict. Possession of a write token is insufficient authority.

### W2 — Placement, commands and outcomes

Use the existing trusted job, not a new job/workflow or privileged PR trigger. Add install step ID `install`; retain restore ID `baseline`. A trusted input-normalization step sets SHADOW_OPERATION using W1, before map/assessment. Triage/start execute immediately after restore, before any map/assessment/scanner work, then perform frontier-only reconciliation with zero reassessments. Map, default assessment, baseline publication, existing assessment-artifact upload and assessment enforcement are skipped for triage/start. Their existing guards are conjoined with `env.SHADOW_OPERATION == 'reconcile'`; ordinary baseline publication remains assessment exit 0/1 only.

For reconcile, step ID `shadow` goes **after baseline publication and before assessment-artifact upload**, guarded by `!cancelled() && steps.install.outcome == 'success' && steps.baseline.outcome == 'success' && env.SHADOW_OPERATION == 'reconcile'`. Thus map/assessment failure does not suppress it, but failed installation/unsafe restore does. Existing assessment enforcement remains independent of shadow status. Reconcile exits 0/2 produce a neutral notice (2 is expected for v1); exit 3 produces a warning and fails only with fail-on-incomplete. Triage/start exit 0 means published/idempotent success, 1 means immutable authorization refusal and job failure, and 2/3 means not published/job failure with same-actor rerun or re-dispatch remedy. All operations produce an explicit published/already_published/refused/not_published summary; cancellation before publication is never success. Start creates no baseline: without scout/state, every operation exits 3 without writing; establish the baseline through the existing assessment path first. Before a start marker, reconcile/triage exit 3 without writing.

Reserve `scout shadow reconcile --root <root> --remote origin --json`, `scout shadow triage --root <root> --remote origin --event <id> --verdict <verdict> --reason <reason> --json`, and `scout shadow start --root <root> --remote origin --reason <receipt-reference> --json`. Authenticated execution context is internal, not mintable by CLI flags/environment assertions. Compose S3 collection/authorization/CAS APIs and the existing store; do not create a second backend. Readiness-only publication preserves the complete baseline assessment tree. No arbitrary code from assessed PR checkouts executes.

### W3 — Triggers, grants and credential boundary

Retain pull_request, main push, cron `23 3 * * *`, and workflow_dispatch; no workflow_run or pull_request_target. Push/schedule/reconcile dispatch run bounded collection; triage/start run only frontier reconciliation after their action. V1 always has Complete=false and cannot advance C, even on quiet nights. Delayed/missed schedules never imply coverage.

Add actions:read to the trusted caller job and matching reusable workflow/job ceilings, retaining contents:write and pull-requests:read. **Every external caller upgrading to that reusable revision must grant actions:read or GitHub fails startup**, regardless of runtime conditions. No PR grant changes, actions:write, issues:write or new secrets. Keep trusted concurrency cancel=false and PR cancel=true. Even cancel=false can replace a pending run: cancelled queued triage publishes nothing; the same actor may rerun the logical action or dispatch a new action after inspecting the summary/state (R-103). Concurrency is not cancellation-cause proof.

Select `persist-credentials: false` for trusted checkout. Git credentials are passed per command, never persisted to disk; GITHUB_TOKEN is step-local only for safe restore/private reads, baseline publication, existing metadata assessment and shadow control-plane operations. The Jev secret remains assessment-only. No scanner process inherits credentials, can read credential-bearing parent state, or can write trusted executables/config/auth/other attempts. Existing broad read-only sandbox mounts alone do **not** prove credential confidentiality: S6/P23 must demonstrate absence of tokens from `.git/config`, runner-temp credential files, process environment and scanner-readable files, plus trusted-byte integrity on Linux/macOS. Missing isolation refuses collection. Do not grant wider tokens before that proof. Existing scout/state ruleset must authorize only intended trusted writers.

### W4 — Settings, bounds and versioning

Release-bound `github-shadow/v1` is the collector eligibility-logic component of ADR-012's selector, recorded with trigger/config/recipe pins. Any change to this version, deadline or budget starts a new interval; pin changes alone do not. V1 has **no event deadline and no finite effective lag** because it has no complete PR-event source. A future source ADR must select/prove both; no engineering lag number enables certification.

The non-terminal-attempt deadline is started_at+7,200,000ms (2 hours, an operational loss bound exceeding the current 30m PR/60m trusted limits, not an API guarantee). Expiry is decided only when the authenticated publishing job's REST started_at is at least that deadline; equality expires. Writer wall time and HTTP Date cannot decide expiry or completeness. Unknown job start/time leaves expiry unmeasured. Known expired attempts produce point gaps; later terminal facts use ADR-012 lateness. No new policy keys, especially no blocking.shadow.workflow; existing min_days/min_pr_runs defaults 14/5 remain unchanged.

### W5 — What v1 collects, and what it cannot certify

Use paginated runs of the pinned caller path with event=pull_request, created-time partitions below GitHub's filtered-search 1,000-result cap, plus all observable attempts/jobs. Detect cap saturation, missing pages, deletion/retention, empty PR bindings (including forks) and permission failures as disclosed population limits/refusals. Original run creation is not job/attempt start. Current PR heads, empty pages, total_count, HTTP Date and artifacts do not prove event completeness. **V1 records no provider PR-event population or event obligations, event_source=none; no attempt accounts an event and C never advances.** Individual facts require authenticated repository/PR/head/start/recipe bindings; missing binding never becomes trusted evidence.

V1 may reassess observed PR heads through the trusted pinned guardian merge-result-versus-B recipe with empty overrides, existing scanner sandbox and exact input/inspection provenance. Persist new authenticated collector attempts and their own would_block events, not fictional historic PR-lane results. Do not derive would_block events from PR artifacts. Process oldest observable heads first, with durable idempotent progress; stop starting work at 40 minutes of the own job's authenticated provider elapsed time. Provider elapsed time must be independently authenticated; if unavailable, do not start reassessment. Bound every assessment by the remaining trusted-job budget and existing scanner timeouts; abandoned work is incomplete, never zero findings. Unprocessed observed heads remain waiting/disclosed, not excluded. Preserve H1/H2 separately when actually observable; never reconstruct missing history from H2. Missing merge/input/output evidence follows ADR-012 comparison-none/gap rules.

A future certifying snapshot needs complete event **and started-attempt** bounds/time, including never-started, skipped, approval-waiting, historical/superseded, bot/fork events and exact cause/config proofs for exclusions. REST-only v1 MUST expose Complete=false. Authenticated facts/triage/refusals/known points may be persisted, but no guessed genesis/frontier, empty complete interval or activation follows. Durable capture/replay infrastructure is unselected and requires another adopted wiring ADR before enabling certification.

**Consequence:** v1's authenticated linked would_block events remain cohort-wide Undecided vetoes even across a later complete interval until authorized triage resolves them. Ship collection and triage together and expose untriaged v1 events per exact cohort in readiness diagnostics. These are not disposable preview events. ADR-012's all-interval vetoes and historical immutability remain unchanged.

### W6 — Operational rollout and start

Ship schema14/manifest-v2 readers/writers, S3 adapter/publication, S4/S5 producer/CLI and S6 boundary proofs in a compatible release, retaining the genuine v13 fixture. Existing platform binaries/checksums, Clawpatch bundle/manifest/checksums and tag-installed scripts remain the only release artifacts. New commands ship in the existing binary. REQ-162/163/168 remain byte-identical. The wiring revision requires scout-version at least the first release containing all shadow commands; the implementation PR records that actual tag and documents it for external callers. Older binary mismatch gives reconcile unavailable/3 (existing fail-on-incomplete handling), triage/start failure; no workflow-side install fallback or new install interface.

Inventory every shared-state reader/writer, including external/local publishers and queued/in-flight/rerunnable old runs. Stop publication, quiesce/cancel old jobs and operationally forbid old reruns/writers. Record identities, workflow/release pins, cancellation/disable evidence, last intact v2 commit and migration result in an immutable rollout receipt referenced by start's reason. Move reusable revisions and caller scout-version/grants together; restore/reconcile subsequent paused state before reopening. Downgrade remedy republishes last intact v2 **and reapplies subsequent state**; newer schema requires writer upgrade, never rollback.

Start is provider-authenticated/current-tip maintainer-authorized under W1, only after receipt/S6 acceptance. Its released binary validates the receipt's immutable digest/reference against the deployed writer inventory/upgrade and no-old-writer evidence; an unchecked free-text assertion is insufficient. Missing evidence refuses. Start publishes a single idempotent per-lineage collection-start marker using ADR-012's provider/CAS stamp formula. A repeated start cannot reset coverage or erase facts. Marker time is authenticated publication time, not a complete frontier; pre-marker facts cannot certify pre-cutover coverage. Reconcile/triage require the marker. Collection and triage are enabled together. V1 remains unmeasured indefinitely; later complete-source adoption must establish its own attested interval/genesis, never backdate to this marker. Adoption alone proves neither deployment nor rollout.

### W7 — P25 adoption gate

`TestADR012WiringAdoptionGate` and the existing infrastructure guardrail classify current governed surfaces against the signed wiring-contract.json baseline plus approved deltas, rejecting every unknown change. Cover triggers/cron, input grammar/defaults/options/forwarding, reusable interfaces, exact job/step conditions, permission ceilings/token boundary, commands/settings, policy keys, release artifacts and governed REQ rows. Existing guardrail assertions must derive from or be checked against the same contract. Positive fixtures include exact W1–W6 and pure library/read-only CLI changes; independent negatives include unknown input/trigger/workflow/grant/key/artifact/REQ text, wrong/superseded ADR, nonzero review/digest mismatch, incomplete source made complete, and old-writer/rerun downgrade.

The explicit final round contains one machine-readable scout-signoff/v1 JSON block: adr, folder, round, open_issues=0, verdict=approved, and path-sorted files with SHA-256. Locate the unique commit in HEAD ancestry that added that final round (all parents, not first-parent only). Read and hash signed blobs at that immutable adoption commit, **not current mutable tracker/index bytes**; current final-round/contract bytes must equal those adoption blobs. Missing/shallow/ambiguous history fails closed with fetch/unshallow remedy. ADR status-line amendments are permitted only under existing rules and do not rewrite adoption blobs. Later amendments use a new folder/contract declaring supersedes; verify each adoption link and revoke superseded authority. Actual documentary adoption authorizes surfaces, not a mock or hard-coded ADR number. P25 state equality allows only baseline plus approved surfaces; additive and destructive deltas both require classification.

Unit fixtures cannot certify live source capability, scanner isolation or all-writer cutover. Implementation needs actual provider refusal/capability receipts and S6 operational evidence before enabling collection; readiness remains unmeasured without a later complete source. No implementation acceptance is replaced by a refusal-only test.
