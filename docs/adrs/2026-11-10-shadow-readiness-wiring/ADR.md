# ADR-015: Wire non-certifying shadow collection and authenticated triage

- **Status:** accepted-form; effective only on this folder's explicit final zero-issue council round
- **Deciders:** agent-decided under owner delegation (R-064)
- **Decided:** 2026-11-10; **sources:** R-064, R-070, R-077, R-100–R-108
- **Delivery:** design only; no Go or workflow changes; owner review pending in editable trackers.

## Decision and limits

Select non-certifying collection/triage wiring left open by ADR-012. The certifying PR-event source remains unselected: production shadow readiness stays unmeasured/exit 2 until a later adopted wiring ADR proves a complete source. This does not narrow ADR-012 or close its implementation acceptance. Missing authenticated complete event/started-attempt bounds or provider time never means ready. No pre-cutover coverage is certified. No external service, App, secret, population exclusion or weakened evidence rule is adopted.

The normative machine copy of W1–W6 is [wiring-contract.json](wiring-contract.json). Both prose and contract are signed; any disagreement is a gate failure, not implementation discretion.

### W1 — Dispatch source, transport and authorization

Extend `scout-nightly.yml` workflow_dispatch with `shadow-operation` (choice `reconcile|triage|start`, default `reconcile`), `shadow-event` (string, default empty), `shadow-verdict` (choice `none|warranted|not_warranted|undecided`, default `none`), and `shadow-reason` (string, default empty). In `scout-guardian-trusted.yml` workflow_call these four inputs are strings with the same defaults; forward operation/verdict using the default fallbacks and event/reason without transformation. The binary revalidates all values. Non-dispatch events treat all four as absent/reconcile. Existing full/refresh-map/authorize-egress meanings remain unchanged for reconcile. Triage/start require all three booleans false. Reconcile requires verdict=none and empty event/reason; triage requires an existing persisted CI event ID with its canonical grammar and verdict other than none; start requires empty event and verdict=none. Triage/start reason is 1–1,000 UTF-8 bytes without control characters. Explicit undecided is an append-only verdict retraction under ADR-012's latest-visible-row rule. Pass data via step env and argument arrays, never interpolate it into executable shell.

Authority is the GitHub-issued executing-attempt context, read by the trusted released binary through step-level env before assessed code/scanners. Bind inputs, event_name, actor_id, triggering_actor, run_id, run_attempt, repository_id, ref, sha and workflow_ref. REST run/attempt must corroborate workflow_dispatch, numeric repository ID, default head_branch/head_sha, caller path and original/triggering numeric actor IDs. Inputs are not REST-verifiable: integrity rests on first-attempt context and ordering. R-104 corrects R-102's unsupported input-reuse premise. The complete pre-action whitelist is checkout, setup-node, release-tag install, token-free prepare-auth, scanner-cache restore, release-tag toolchain provisioning, safe state restore and pure shadow-inputs normalization. No assessed code/scanner runs before triage/start; never use artifacts or local actor/trusted flags as authority.

Logical action=(numeric repository ID, run ID), not run_attempt. Require original numeric actor ID=executing numeric actor ID. Resolve the current login from that numeric identity on every CAS retry and apply REQ-23 exact-name maintainer/CODEOWNERS matching at the current protected default tip; record ID, login used and policy revision. Prove protected-default execution/source ancestry and refuse/log missing proof, mismatch or revoked/nonmaintainer author. The first terminal accepted or immutable refusal record for a logical action is final; later attempts publish nothing. For an unpublished action, v1 refuses every run_attempt>1 and directs a fresh dispatch; no undocumented input-reuse assumption authorizes it. Enabling unpublished-action full/job reruns requires a later reviewed transport capability amendment and actual input-integrity proof. At most one row/event/publication; replay cannot overtake a newer verdict. Possession of a write token is insufficient authority.

### W2 — Placement, commands and outcomes

Use the existing trusted job, not a new job/workflow or privileged PR trigger. Add install step ID `install`; retain restore ID `baseline`. A trusted input-normalization step sets SHADOW_OPERATION using W1, before map/assessment. Triage/start execute immediately after restore, before any map/assessment/scanner work, then perform frontier-only reconciliation with zero reassessments. Map, default assessment, baseline publication, existing assessment-artifact upload and assessment enforcement are skipped for triage/start. Their existing guards are conjoined with `env.SHADOW_OPERATION == 'reconcile'`; ordinary baseline publication remains assessment exit 0/1 only.

For reconcile, step ID `shadow` goes **last, after assessment-artifact upload and assessment enforcement**, with timeout-minutes=2 and guard `!cancelled() && steps.install.outcome == 'success' && steps.baseline.outcome == 'success' && env.SHADOW_OPERATION == 'reconcile'`. Thus assessment failure does not suppress inventory, but unsafe restore/installation does; shadow cannot consume the time reserved for already completed artifact/enforcement steps. Assessment enforcement uses `!cancelled() && env.SHADOW_OPERATION == 'reconcile' && steps.assessment.outcome != 'skipped'`. Reconcile 0/2 is neutral (2 deliberately ignores fail-on-incomplete); 3 warns/fails only with fail-on-incomplete. Existing assessment 2/3 handling is unchanged. Triage/start 0 means published/idempotent, 1 means immutable refusal/job failure, and 2/3 means not_published/job failure with fresh-dispatch/prerequisite remedy. Summaries distinguish published/already_published/refused/not_published; cancellation never means publication. Start never creates the baseline: absent scout/state, operations exit 3 without writes. Before a marker reconcile returns not_started/unmeasured/2 without writes; triage returns 3.

Input normalization has ID `shadow-inputs`, immediately after restore/before actions or map, guarded by `!cancelled() && steps.install.outcome == 'success' && steps.baseline.outcome == 'success'`. The released `scout shadow validate --json` is a pure grammar check (no store/network/publication), consuming only step-bound operation/event/verdict/reason plus the three booleans and event_name. On success its bounded JSON supplies operation; workflow writes that enum to GITHUB_ENV as SHADOW_OPERATION. On invalid input it sets SHADOW_OPERATION=invalid, emits not_published/invalid_inputs summary and exits 3; all governed assessment/action steps skip, with no publication. Non-dispatch inputs normalize to reconcile. This validation helper is a reserved command shipped with the same minimum compatible release, not an authority mint.

Reserve `scout shadow reconcile --root <root> --remote origin --json`, `scout shadow triage --root <root> --remote origin --event <id> --verdict <verdict> --reason <reason> --json`, and `scout shadow start --root <root> --remote origin --reason <receipt-reference> --json`. Authenticated execution context is internal, not mintable by CLI flags/environment assertions. Compose S3 collection/authorization/CAS APIs and the existing store; do not create a second backend. Readiness-only publication preserves the complete baseline assessment tree. No arbitrary code from assessed PR checkouts executes.

### W3 — Triggers, grants and credential boundary

Retain pull_request, main push, cron `23 3 * * *`, and workflow_dispatch; no workflow_run or pull_request_target. Push/schedule/reconcile dispatch run bounded collection; triage/start run only frontier reconciliation after their action. V1 always has Complete=false and cannot advance C, even on quiet nights. Delayed/missed schedules never imply coverage.

Add actions:read to the trusted caller job and matching reusable workflow/job ceilings, retaining contents:write and pull-requests:read. **Every external caller upgrading to that reusable revision must grant actions:read or GitHub fails startup**, regardless of runtime conditions. No PR grant changes, actions:write, issues:write or new secrets. Keep trusted concurrency cancel=false and PR cancel=true. Even cancel=false can replace a pending run: cancelled queued triage publishes nothing; inspect summary/state and dispatch a new action (R-103, corrected rerun remedy R-104). Terminal logical actions remain deduplicated; unpublished-action reruns are not authorized in v1. Concurrency is not cancellation-cause proof.

Select `persist-credentials: false` for trusted checkout. Git credentials are passed per command using an ephemeral trusted credential helper, GIT_ASKPASS or stdin, never in argv and never persisted to scanner-readable disk; GITHUB_TOKEN is step-local only for safe restore/private reads, baseline publication, existing metadata assessment and shadow control-plane operations. The Jev secret remains assessment-only. No scanner process inherits credentials, can read credential-bearing parent/sibling state, or can write trusted executables/config/auth/other attempts. Existing broad read-only sandbox mounts alone do **not** prove credential confidentiality: S6/P23 must demonstrate absence of tokens from `.git/config`, runner-temp credential files, own and other processes' argv/environment (`/proc`/ps included) and scanner-readable files, plus trusted-byte integrity on Linux/macOS. Missing isolation refuses collection. Do not grant wider tokens before that proof. Existing scout/state ruleset must authorize only intended trusted writers.

### W4 — Settings, bounds and versioning

Release-bound `github-shadow/v1` is the collector eligibility-logic component of ADR-012's selector, recorded in diagnostics and any authorized publication provenance. A settings/eligibility change requires a new reviewed version; eligibility changes start a new interval, pin changes alone do not. **V1 has no attempt/event collection deadline, no finite effective lag and no reassessment budget**: it collects no readiness attempt facts or provider-event obligations. Do not ship inert timing constants. A later source/reassessment ADR must select justified deadlines/lag, authenticated B/H/merge-result bindings, per-head provider attempt identity and scheduling without changing ADR-012 silently. Existing 14/5 minima and policy keys remain unchanged; never add blocking.shadow.workflow.

The inventory control-plane step has timeout-minutes=2 and at most 100 API requests per invocation, stopping when authenticated rate-limit remaining falls below 200. These are operational resource caps, not provider consistency/time attestations. Partial inventory reports limits, never complete coverage. Run it after assessment artifact upload and enforcement so it cannot starve either; ordinary job timeout remains 60 minutes. Cancellation of this last step means unavailable inventory, not successful collection.

### W5 — What v1 writes, and what it cannot certify

V1 may inspect paginated runs of the pinned caller path with event=pull_request and run creation at/after the start marker, plus their observable attempts/jobs, within W4's request/time caps. Sort observable records by original creation then numeric run/attempt/job identity; detect capped/saturated partitions, missing pages, deletion/retention, empty fork PR bindings and permission failures as explicit diagnostic population limits. These are inventory diagnostics only, not provider PR-event population, completed assessment evidence or zero findings.

**Exact durable write set:** an authorized start marker; authorized triage rows on already persisted authenticated CI events; immutable action refusals/idempotence records and their normal S3 publications. V1 inventory writes **no PRRunFact, would_block event/link, provider PR-event obligation, gap point, complete interval or frontier**. It does not reassess PR heads or consume PR artifacts as findings. event_source=none, Complete=false, C unchanged and readiness unmeasured/exit 2. It reports reassessment_unavailable rather than producing fictional historical results. This deliberately settles the runnable v1 boundary; a future reassessment design is not pre-authorized by supplying a clock alone.

A later adopted source/reassessment ADR must prove complete event and started-attempt bounds/time including skipped/unstarted/fork/bot/approval/superseded heads, choose authenticated B and its reachability, exact guardian parity, a provider attempt identity per assessed observation (one trusted job cannot invent multiple identities), deadlines/lag/horizon and usable time/dispatch capacity. It must continue the **same state lineage** and establish a new attested interval origin/first frontier, not a replacement lineage genesis. No pre-marker coverage, guessed completeness or activation follows from v1. Durable capture/replay infrastructure remains unselected.

Existing/imported authenticated linked events remain cohort-wide Undecided vetoes until authorized triage, even in later complete intervals; preserve them and their triage in the same lineage. V1 generates no additional event backlog, so serial single-event triage does not race newly generated v1 vetoes. Show unresolved events by cohort and publication summaries; operators submit one action at a time and confirm publication before the next, rather than treating queued dispatches as a delivery ledger. Full ADR-012 acceptance remains open.

### W6 — Operational rollout and start

Ship schema14/manifest-v2 readers/writers, S3 adapter/publication, S4/S5 producer/CLI and S6 boundary proofs in a compatible release, retaining the genuine v13 fixture. Existing platform binaries/checksums, Clawpatch bundle/manifest/checksums and tag-installed scripts remain the only release artifacts. New commands ship in the existing binary. REQ-162/163/168 remain byte-identical. The wiring revision requires scout-version at least the first release containing all shadow commands; implementation records the actual minimum tag and release command test. The token-free workflow askpass helper below does not require a newer binary for existing restore/publish. Old binaries lack validate/shadow commands: normalization exits 3 before any assessment/publication and reports upgrade required; do not silently continue. Caller grants, reusable revision and compatible release move together; no installation fallback.

Inventory every shared-state reader/writer, including external/local publishers and queued/in-flight/rerunnable old runs. Stop publication, quiesce/cancel old jobs and operationally forbid old reruns/writers. Record identities, workflow/release pins, cancellation/disable evidence, last intact v2 commit and migration result in an immutable rollout receipt referenced by start's reason. Move reusable revisions and caller scout-version/grants together; restore/reconcile subsequent paused state before reopening. Downgrade remedy republishes last intact v2 **and reapplies subsequent state**; newer schema requires writer upgrade, never rollback.

Start is provider-authenticated/current-tip maintainer-authorized under W1, only after receipt/S6 acceptance. Missing evidence refuses. Start publishes one idempotent per-lineage collection-start marker with ADR-012's provider/CAS stamp formula. Repeated start cannot reset coverage or erase facts. Marker time is authenticated publication time, not a frontier; reconcile/triage require it. V1 remains unmeasured indefinitely. A later complete source continues the same lineage and establishes an attested interval origin/first frontier, never a new lineage genesis or backdated coverage. Adoption proves neither deployment nor rollout.

The receipt reference grammar is `git:<40-hex-commit>:<repo-relative-path>#sha256=<64-lower-hex>` (path below `docs/operations/shadow/`, no traversal/symlinks). Fetch it only from this authenticated repository; its commit must be reachable from the current protected default tip. Receipt JSON schema `scout-shadow-rollout/v1` binds numeric repository ID, state ref/genesis lineage, migration state commit, deployed workflow/release immutable commits/digests, complete declared writer inventory, old-run cancellation/disable records, minimum compatible binary version, Linux/macOS S6 evidence commit/path/digests and an explicit `external_inventory_and_rerun_prohibition_attested:true`. API checks validate repository/ref/commit ancestry, known GitHub writer pins, run states and evidence blob digests. External/local writer completeness and prohibition are **current-tip-maintainer operational attestations**, not facts GitHub REST can prove; start's authorized actor explicitly adopts them. Unknown fields/schema, absent evidence, hash/binding mismatch, unupgraded listed writer or observable old active run refuse. The protected default-branch review of that receipt plus the freshly authorized start action establishes its trust; digest alone does not. A changed receipt requires a new start action before an initial marker, not mutation of an existing marker.

For a store with no prior readiness publication, receipt lineage_genesis is null and start requires the readiness history to remain empty through CAS; the normal S3 first-publication mechanism establishes genesis and records it in the marker. Otherwise receipt genesis must equal the established lineage. Receipt also requires `last_intact_v2_commit` (an authenticated scout/state ancestor) and `migration_result` with its evidence digest. Local/external writer inventory and ruleset/rerun prohibition remain explicit operational attestations adopted by the authorized start actor.

Credential mechanism: a trusted token-free `prepare-auth` workflow step, after install/before restore, creates `$RUNNER_TEMP/scout-auth/askpass` outside the workspace. It returns fixed username x-access-token or reads SCOUT_GIT_TOKEN from its step environment for a Git password prompt; the helper contains no credential and is not a release artifact. Safe restore, baseline publish and shadow state/Git operations receive step-local SCOUT_GIT_TOKEN plus GIT_ASKPASS pointing there and GIT_TERMINAL_PROMPT=0; never put a token in argv/config/file. Provider REST uses step-local GITHUB_TOKEN. Restore distinguishes git ls-remote exit 0 (restore), 2 (branch absent) and every other status (authentication/network error: fail restore, no fallback baseline). No scanner inherits either token. Exact helper/step binding and read/write/process isolation are S6/P25 gates, not assumed from read-only mounts.

### W7 — P25 adoption gate

`TestADR012WiringAdoptionGate` and the existing infrastructure guardrail classify current governed surfaces against the signed wiring-contract.json baseline plus approved deltas, rejecting every unknown change. Cover triggers/cron, input grammar/defaults/options/forwarding, reusable interfaces, exact job/step conditions, permission ceilings/token boundary, commands/settings, policy keys, release artifacts and governed REQ rows. Existing guardrail assertions must derive from or be checked against the same contract. Positive fixtures include exact W1–W6 and pure library/read-only CLI changes; independent negatives include unknown input/trigger/workflow/grant/key/artifact/REQ text, wrong/superseded ADR, nonzero review/digest mismatch, incomplete source made complete, and old-writer/rerun downgrade.

The explicit final round contains one fenced scout-signoff/v1 JSON block: adr, folder, round, open_issues=0, verdict=approved, and path-sorted files with SHA-256. The gate selects the highest N among exactly named `round-N.md` files; it must contain exactly one block whose round equals N and folder/ADR match. A higher pending/unsigned round fails closed. Historical lower-round signatures remain immutable evidence, not current authority; signoff blocks in response/non-round files are rejected. Locate the unique commit in HEAD ancestry that added that final round (all parents, not first-parent only). Read and hash signed blobs at that immutable adoption commit, **not current mutable tracker/index bytes**; current final-round/contract bytes must equal those adoption blobs. Missing/shallow/ambiguous history fails closed with fetch/unshallow remedy. ADR status-line amendments are permitted only under existing rules and do not rewrite adoption blobs. Later amendments use a new folder/contract declaring supersedes; verify each adoption link and revoke superseded authority. Actual documentary adoption authorizes surfaces, not a mock or hard-coded ADR number. P25 state equality allows only baseline plus approved surfaces; additive and destructive deltas both require classification. Negative fixtures independently mutate approved REQ rows, each operation condition, final-round selection and every machine surface.

Unit fixtures cannot certify live source capability, scanner isolation or all-writer cutover. Implementation needs actual provider refusal/capability receipts and S6 operational evidence before enabling collection; readiness remains unmeasured without a later complete source. No implementation acceptance is replaced by a refusal-only test.
